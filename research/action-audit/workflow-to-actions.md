1. **Start and branch selection:** use the [model-brief procedure](point-01-model-brief.md) to bind purpose, feature requirements and actual source inputs. Each linked operation states prerequisites and checks; the original route order alone does not establish that its handoffs are satisfied.
2. **Alternatives and combinations:** retain each candidate's source subset, purpose, geometry representation, accuracy target and resource record. A vision-language model examines located source evidence and software comparison results before proposing feature selection or combination. Validate the combined revision with the relevant numerical and independent semantic checks.
3. **Computing demand:** [manual-effort order](../workflows/details/by-human.md) and [local-computing order](../workflows/details/by-compute.md) retain their original qualitative classifications. Action resource fields supply the input-size and algorithm conditions. These classifications are analyst judgments; measured runs require their own receipts.
4. **Evidence:** action definitions and helper contracts are implementation proposals. Point receipts report the executed static document/source checks. Original contract findings are retained in each designer/independent review.
