## 1. Findings for the point-07 procedure

1. **Capture identity precedes reconstruction.** Retain original photograph/video/depth bytes, frame/time mapping, camera/sensor metadata, masks, calibration and every preprocessing transform. Link a source feature to its original pixels or depth samples before using a filtered cloud or mesh as evidence. The [reconstruction assessment](/home/leo/projects/3dmodeling/research/reconstruction.md) and [RGB-D/video dossier](/home/leo/projects/3dmodeling/research/workflows/details/rec-r02.md) establish the source categories and acquisition checks.
2. **Calibration, reconstruction scale and surface accuracy have different evidence.** Calibration describes the applicable camera model, intrinsics/distortion and camera state. Controls establish/check the reconstruction's scale/frame and local dimensions. Surface checks concern identified reconstructed regions and independent evidence. Preserve fit/control/check roles, units and source uncertainty. The [calibrated-photo dossier](/home/leo/projects/3dmodeling/research/workflows/details/rec-r01.md) keeps calibration-target units separate from the object's reconstruction scale.
3. **Evaluation independence is a recorded dependency.** An image can be excluded from appearance training while participating in camera estimation. Its appearance result then shares the pose/calibration source. Two reconstruction branches can share photographs, masks, poses, controls or a learned checkpoint. Record these shared dependencies beside comparison results. An independent physical dimension, another captured view or a separately acquired scan retains its actual acquisition and fitting role.
4. **Observed samples and constructed surfaces retain their method.** A depth frame contains sensor samples under calibration; SfM/MVS estimates geometry from image correspondences; TSDF integrates samples into a voxel field and extracted surface; meshing interpolates between points. Filtering, smoothing, gap filling and decimation each create a new derivative with source-region/feature lineage. Preserve the input and changed/retained required features.
5. **Learned predictions and trained appearance scenes have explicit output types.** DA3 produces predicted depth/camera/cloud outputs under the selected variant. A single-image model generates a proxy with inferred backsides. Gaussian splats and NeRF fit appearance from captured views. Geometry extracted from a trained representation receives its own method/version, artifact and checks. The [learned-depth comparison](/home/leo/projects/3dmodeling/research/workflows/details/rec-r05.md), [scene dossier](/home/leo/projects/3dmodeling/research/workflows/details/rec-r08.md) and [single-image dossier](/home/leo/projects/3dmodeling/research/workflows/details/rec-r10.md) provide these separate branches.
6. **A rendered/generated view is a derived output with a camera and source model.** Its silhouette, colour or predicted depth can be compared with a real captured source under a recorded camera. Additional renders of the same candidate keep that common dependency. Record a real acquisition, generated reference, reconstruction render and synthetic validation fixture by their actual origin.
7. **Broad operation names retain explicit stage contracts.** DOM-20 declares `photo-set` input and `camera-solution` plus `point-cloud` outputs; video sampling is REC-04 and mesh construction is an explicit REC-17/DOM-28 branch. DOM-21 declares `point-cloud` output; REC-06 supplies the explicit TSDF/mesh branch. DOM-22 declares `gaussian-scene`; REC-20/DOM-30 supply `nerf-scene`. Preserve the [original domain contracts](/home/leo/projects/3dmodeling/research/workflows/domain-paths.json) while documenting those handoffs.
8. **Splatfacto export capability is method/version-specific.** The registered Splatfacto page supports Gaussian PLY and reports mesh/point-cloud export as unsupported; the generic Nerfstudio export page contains conflicting wording. Use the exact selected method/version and documented output. The separate MVS or calibrated-depth surface branch retains its own geometry evidence. The [round-two](/home/leo/projects/3dmodeling/research/sources/round-02/reconstruction-sources.json) and [round-three](/home/leo/projects/3dmodeling/research/sources/round-03/reconstruction-detail-sources.json) registers preserve the source conflict.

## 2. Proposed evidence package and VLM action

A **VLM — vision-language model** processes images and language together. Here it associates source features across captures and derived representations, interprets coverage/motion/occlusion, compares candidate methods and proposes source-linked selection. Software computes camera models, poses, depth, fusion, meshes, training outputs and numerical checks. A text-only reasoning model can compare structured records where image content adds no required evidence.

| Evidence group | Concrete retained fields |
| --- | --- |
| Goal and feature criteria | Brief revision, output purpose, named components/features/regions, required representation/detail, dimensional/angular/surface/appearance criteria, units and source/status for each requirement |
| Raw capture | Exact file/hash, original URL/local source, rights record, acquisition time, capture/camera/sensor identity, original pixels/depth values and source frame/timestamp mapping |
| Video sampling | Original video/stream, selected frame index and presentation timestamp, extraction/selection settings, frame hash, inclusion/exclusion reason, exposure/blur/view coverage and duplicate relationship |
| Image preparation | Original/processed image IDs, dimensions, crop/rotation/resize/undistortion mappings, validity mask, pixel convention, colour/background processing and tool/settings/version |
| Camera solution | Camera/lens/focus/zoom/stabilization state, calibration source/revision, intrinsics/distortion model and coefficients, parameter order, image associations, refined/fixed parameter policy, pose direction/axes and numerical readback |
| Depth sequence | Sensor-native depth interpretation/scale/units, range/invalid-value mask, RGB/depth intrinsics, RGB-to-depth extrinsics, frame time association, synchronization evidence, pose trajectory and calibration revision |
| Controls and checks | Named physical feature/point/length, measured value/unit/frame, acquisition/method/uncertainty, image/sample correspondence, and separate calibration/fit/scale/registration/training/evaluation roles |
| Sparse/dense evidence | Feature/track/match IDs, image observations, camera component, sparse/dense point IDs, depth-map provenance, masks/confidence, sample coverage, frame/scale and actual reconstruction options |
| Geometry derivative | Input/output hash, selected source sample/face IDs or retained region mapping, operation/parameters, normal/topology changes, interpolated/filled/removed regions, decimation settings and per-feature change receipt |
| Learned model | Source-code and checkpoint identity/hash, exact variant, source/checkpoint terms, local/remote execution location, input/mask/preprocessing, seed/settings, model-derived depth/camera/confidence and exact output representation |
| Trained scene | Captured/processed image IDs, camera solution, training/evaluation membership, scene bounds/normalization, initialization, pose refinement, configuration/checkpoint, method/version and supported export |
| View comparison | Real/generated/rendered origin, source image/model/checkpoint hash, camera/pose revision, pixel mapping, visibility/occlusion/region masks, full-view/crop association and numerical comparison rows |
| Branch selection | Common sources/dependencies, per-feature correspondence, candidate artifacts, measured differences, retained feature/field and source branch, reasoning result, alternatives and resulting merged revision |

Proposed VLM sequence:

1. Read the goal and source captures with full-view context. Identify the same physical feature/component across frames; preserve repeated/symmetric/occluded alternatives with source pixel regions and time/frame identity.
2. Review capture coverage by required feature and viewpoint, blur/exposure, moving objects, reflections and unobserved regions. Propose a bounded frame/mask/region selection with its source evidence and goal.
3. Associate controls with exact physical features and source observations. Read each control's fit/check role, units, frame and uncertainty before interpreting a residual or scale.
4. Examine camera paths, sparse tracks, depth alignment, coverage and regional residual reports. Propose whether a discrepancy belongs to correspondence, preprocessing/calibration, pose/scale, motion, sensor timing, surface behavior or a derivative edit, with the evidence supporting that diagnosis.
5. Compare source views, labelled cloud/mesh regions, candidate renders and numerical checks for the same feature. Retain the actual representation and source/model dependencies of each candidate.
6. Propose whole-candidate selection or compatible feature/evidence combination within the stated purpose. Give every retained field/feature its source branch and reason; preserve conflicting candidates and the exact intent decision required where applicable.
7. Review the new merged/saved revision against original captures, required measurements and independent controls. A separate semantic reviewer checks component/feature correspondence and evidence labels; numerical checks retain their own results.

## 5. Independent controls, real views and shared dependencies

| Evidence role | Recorded participation and comparison meaning |
| --- | --- |
| Calibration source | Camera-state/target/image evidence used to estimate intrinsics/distortion; applicable processed-image mapping retained |
| Fit/scale/registration control | Explicit source feature/point/length used to determine pose/scale/registration; its residual reports that fit |
| Held-out physical measurement | Named measured feature excluded from the affected fit/parameter choice; acquisition, uncertainty, scene revision and any shared calibration recorded |

1. Freeze fit, training, selection and evaluation memberships before the comparison. A control repeatedly used to choose parameters has its selection role recorded; a new evaluation set receives its own source revision.
2. Retain source control coordinates and original image/sample associations. Check that masks, crop/undistortion and decimation preserve the relevant feature or explicitly revise its derived association.
3. Record camera calibration and pose uncertainty/dependencies beside evaluation results. A captured image excluded from radiance training but included in camera estimation retains that exact participation.
4. Compare regional/control residuals in the stated units and source frames. Report spatial distribution, maximum/quantiles or the requested statistics with sampling/threshold configuration; source uncertainty and reconstruction residual keep separate fields.
5. Assess coverage and correspondence beside aggregate fit or image metrics. A required bore/opening can be absent or incorrectly associated while aggregate appearance or bounds remain similar.
6. Keep real and generated source evidence labelled through later edits. A generated back view used to guide an authored feature retains its generator/model lineage; actual measurements and captured views retain their own source authority and scope.

Proposed source-based selection/merge procedure:

1. Give candidates the same frozen brief, required feature set and evaluation evidence. Retain each branch's different detail, purpose, permitted approximation and compute conditions.
2. Convert units/frames through explicit transforms and associate the same physical feature before comparing candidates. Preserve source image/depth/sample/face identities and transform direction.
3. Compare source correspondence, local coverage, required-feature geometry and physical controls first for a precision goal; compare real captured views and declared viewing coverage for an appearance goal. Record inter-estimate agreement separately from physical/reference checks.
4. Supply the VLM source views/regions, candidate artifacts/renders, provenance, measurement reports and dependency map. Return evidence-linked whole-candidate selection, compatible field/feature combination or retained alternatives. A new intent decision becomes the exact dependent question.
5. Preserve every selected feature's source branch, source region/sample/measurement, transform and evidence class. A merged source-region map records actual membership/weights when exposed; an approximate region/nearest-surface association records its method and resolution. Preserve the original data when the selected API exposes only a coarse mapping.
6. Combine compatible evidence/geometry under the stated intent. Shared calibration/pose errors remain recorded in both contributing branches. A contradictory surface/scale estimate remains a separate candidate until a source-supported selection rule or scoped decision resolves it.
7. Create the merged revision and new output hashes. Read back and remeasure required dimensions/surfaces/frames, source-feature correspondence, camera projections and output topology/representation. A separate semantic reviewer compares original evidence, component boundaries, inferred/observed labels and the merged map.
8. For refinement, name the changed feature/parameter, objective, fixed evidence, check settings and sourced stop criterion. Preserve failed and passing results with their artifact revisions. A changed evidence/pose/scale configuration creates a new comparison branch.

Proposed checks through surface edits and decimation:

1. Preserve the pre-edit cloud/mesh, source frame and exact selected region. Record discarded sample/face IDs, derivative map and operation/settings for crop, filtering, normal changes, smoothing, filling, remeshing or decimation.
2. Inspect required sharp edges, thin features, bores, openings, component boundaries and contact regions in labelled source/derived views. Map a concern to a named geometry query.
3. Measure local changes using the stated directional sampling/distance method, required dimensions and topology. Record coverage and hole/fill masks; compare the original captured projections and independent controls under the same camera/frame.
4. Recheck the merged/saved mesh and its required downstream role. New filled/interpolated surfaces retain their method/source status. CAD parameters consume their actual governing measurements and source-feature map.

## 7. Failure detection, recovery and source-change effects

| Future failure/change | Detection and retained evidence | Bounded response and invalidated dependencies |
| --- | --- | --- |
| Frame selection loses required viewpoint | Source timeline, selected frames, coverage/blur report and required-feature regions | Revise the named frame subset; recheck camera matching and affected downstream geometry/training |
| Dynamic objects or incorrect masks affect features | Original/masked images, time sequence, tracks/depth regions and component IDs | Review exact object/region masks and stable-scene selection; rerun affected matches/poses/fusion/training |
| Calibration/image mapping conflict | Source calibration, preprocessing chain, expected/actual camera readback and regional residuals | Resolve named crop/size/pixel/distortion/focus input; invalidate dependent poses, projections and reconstruction artifacts |
| Sparse solve fragments or produces wrong repeated-feature match | Camera components, source tracks/matches, alternative poses and control differences | Revisit exact correspondence/overlap/mask region or supplied pose route; preserve separate components until a sourced transform connects them |
| RGB/depth timing/extrinsic mismatch | Timestamps, synchronization/trajectory, RGB/depth edge overlays and calibration revision | Inspect exact frame association/transform; recheck affected trajectory, clouds, fusion and derived measurements |
| Loop drift or nonuniform residual pattern | Trajectory, distributed fit/check controls, local residual maps and units | Revisit source calibration/pose/registration; retain spatial disagreement and alternatives; regenerate affected metric surfaces |
| Dense holes/double layers/false surfaces | Depth maps, view coverage, confidence/masks and source images | Diagnose the affected texture/occlusion/motion/pose region; select the supported evidence path or revised capture/processing stage |
| Meshing/decimation removes or fills a required feature | Pre/post geometry hashes, region/sample/face map and local measurements | Revise the bounded meshing/edit parameters or retain the source representation; recheck affected features, derivatives and CAD handoff |
| Learned branches disagree | Exact variant/checkpoint, shared-input map, controls, poses/confidence and regional comparisons | Preserve estimates; inspect the named source/scale/camera/feature conflict and apply the source-based selection rule |
| Trained scene ghosts or fails captured-view comparison | Source/evaluation membership, camera mapping, pose refinement and region renders | Inspect source coverage/pose/exposure/mask association; create a new bounded training candidate and repeat fixed checks |
| Requested export differs from supported method | Exact method/version, registered source conflict, command/result and actual artifact | Use the explicitly supported output branch or separate geometry route; invalidate the assumed downstream representation |
| Capture/checkpoint/controls or settings change | Immutable earlier source pin, changed-field receipt and dependency map | Create new evidence/artifact revision; recheck affected poses, scale, source maps, geometry/training, selection and exports |
| Interrupted operation or mismatched view/readback revision | Stable operation/call ID, input hashes, checkpoint/stage state and partial result | Query actual stage/artifact state before repeating; resume the incomplete bounded stage and rebind its dependent results |

A source change preserves the earlier checked artifact and unaffected results. A new model/checkpoint changes prediction/scene dependencies even when the source images remain equal. A changed calibration/pose/scale invalidates dependent geometry/projection comparisons; a changed mask/selection invalidates participating reconstruction/training stages; a changed mesh edit invalidates affected feature/consumer checks.

Proposed repeatable software components are capture/preprocessing manifests, camera/trajectory readback comparison, fit/check-role audit, sample/feature lineage, regional geometry/edit comparison, real-versus-rendered evaluation receipts, representation/export dispatch and dependency invalidation.
