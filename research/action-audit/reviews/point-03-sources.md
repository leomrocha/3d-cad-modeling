## Findings for the procedure designer

1. **DXF entities and declared units (CAD-08, DOM-03):** [ezdxf entity queries](https://ezdxf.readthedocs.io/en/stable/tasks/query.html) use a layout's `query()` to select DXF entities by type and attributes. [ezdxf unit documentation](https://ezdxf.readthedocs.io/en/stable/concepts/units.html) says DXF coordinates are unitless, document/modelspace units are declared by `$INSUNITS`, and block insert unit scaling must be applied explicitly. The ezdxf unit page labels its cross-application observations as based on BricsCAD experiments. Record entity types, space/layer/block context, insert transforms and the unit declaration separately. A unit declaration alone does not establish measured scale.
2. **SVG dimensions and transforms (CAD-08, DOM-03):** the [W3C SVG 2 coordinate specification](https://www.w3.org/TR/SVG2/coords.html) defines viewport dimensions in abstract user units, with `viewBox`, element `transform` and nested viewport mappings changing the coordinate system. Absolute SVG units follow CSS unit definitions, including 1 inch = 96 CSS pixels. Preserve the outer viewport, viewBox, nested viewports, transforms and any physical width/height values when deriving profile dimensions; a number in SVG user units is not automatically a millimetre measurement. CAD-09 consumes the derived profile for constraint authoring.
3. **Constrained profiles (CAD-09, DOM-03):** the [FreeCAD Sketcher scripting page](https://github.com/FreeCAD/FreeCAD-documentation/blob/main/wiki/Sketcher_scripting.md) demonstrates `doc.addObject("Sketcher::SketchObject", ...)`, `sketch.addGeometry(...)`, `sketch.addConstraint(Sketcher.Constraint("Coincident", ...))`, and `doc.recompute()`. Its example adds one coincidence relation to three line segments; the page does not show a closed, fully constrained profile or solver diagnostic result. The repository reports itself archived on 2026-04-01, so this is retained API guidance, not a current version guarantee. CAD-10 and CAD-13 are downstream only when their operation records explicitly accept the constrained-sketch output.
4. **Profile extrusion to kernel part (CAD-10, DOM-04, DOM-40):** [build123d operations](https://build123d.readthedocs.io/en/latest/operations.html) describe `extrude(to_extrude, amount, dir, until, target, both, taper, ...)` with Sketch/Face input and Part output. The page states operations create new objects and work in Builder and Algebra modes; its served `latest` documentation identified a development build. This operation creates a kernel part from a profile and does not itself supply Sketcher constraint status or validate source correspondence.
5. **CadQuery DXF intake (CAD-08, DOM-03), STEP exchange (DOM-05) and validity check (CAD-13):** [CadQuery import/export docs](https://cadquery.readthedocs.io/en/stable/importexport.html) show `importers.importDXF(...).wires().toPending().extrude(10)`; all layers are imported by default unless include/exclude lists are given. The `importDXF` operation supplies the profile for CAD-08 and DOM-03; extrusion is the separate downstream CAD-10/DOM-04/DOM-40 operation. The same page documents STEP import unit conversion, STEP Workplane/assembly export and assembly names/colors behavior for DOM-05: import converts declared units to millimetres by default or a selected unit; export supports Workplane and assembly output; default assembly export nests the structure and retains colors but uses generated names instead of supplied child names. STL, AMF and 3MF are described as mesh formats. The [CadQuery Shape API](https://cadquery.readthedocs.io/en/stable/classreference.html) defines `Shape.isValid()` as detecting defects on a shape and its subshapes through OCCT's `BRepCheck_Analyzer`, relevant to CAD-13. That check reports kernel integrity; it does not prove drawing agreement, correct scale or manufacturing suitability.
6. **OpenSCAD CSG and mesh handoff (CAD-15, DOM-40):** the [official OpenSCAD documentation index](https://openscad.org/documentation) links its language reference, User Manual and command-line section. The index page inspected here provides no CLI command example; the existing [source-register record for OpenSCAD documentation](../../sources/source-register.md#src-ce92c7f02e89) records prior manual inspection for command-line rendering/export. The relevant handoff is source-defined CSG and its mesh export; retain `.scad` as the editable parametric source and label STL/3MF results as meshes. Do not map that output to a constrained sketch or analytic B-rep solid.

## Representation handoffs

1. **DXF/SVG profile extraction (CAD-08, DOM-03) → constrained sketch (CAD-09, DOM-03):** import/vector parsing supplies candidate edges or paths. A constrained sketch additionally needs feature association, closure/continuity checks, unit/frame decisions, and explicit geometric or dimensional constraints with solver readback. The cited FreeCAD example establishes the construction calls, not the completed constraints or solver status. CAD-10/CAD-13 may consume the sketch only where their input contracts explicitly allow it.
2. **Profile extrusion to kernel part (CAD-10, DOM-04, DOM-40):** build123d documents Sketch/Face extrusion to a Part; CadQuery's DXF example documents profile import and extrusion in one scripted chain (CAD-08/DOM-03 extraction followed by part creation). The source profile, layers/paths, unit conversion, extrusion direction and height remain linked inputs. A valid kernel shape and source-profile correspondence are separate checks.
3. **STEP exchange (DOM-05) and shape validity (CAD-13):** CadQuery's STEP import/export unit, assembly and naming options belong to the STEP exchange operation. Its `Shape.isValid()` reports kernel defects for shape/subshapes; separate dimensions, units and source-feature checks remain required.
4. **Parameterized CSG → mesh (CAD-15, DOM-40):** OpenSCAD's documented route is script-defined constructive solid geometry. Mesh output carries tessellated geometry; it does not retain a Sketcher constraint system or analytic B-rep feature history.
5. **Software terms:** reuse the existing source-register records for ezdxf, FreeCAD, build123d, CadQuery and OpenSCAD license evidence. The FreeCAD records already note conflicting LGPL version wording; resolve terms against the selected distribution before use. This fresh documentation check did not inspect any license page.
