## Findings for the procedure designer

1. **Assembly creation and placement (CAD-12, DOM-07):** the [FreeCAD Assembly Workbench documentation](https://github.com/FreeCAD/FreeCAD-documentation/blob/main/wiki/Assembly_Workbench.md) describes root and nested assemblies, component insertion, links to source objects, and named joint types. This supports an assembly workflow whose records distinguish component definitions from assembly occurrences and their constraints. The FreeCAD documentation repository was archived on 2026-04-01; this page is capability documentation, not evidence for a selected current build or its runtime.
2. **STEP import/export settings and units (DOM-38, DOM-39):** the [FreeCAD import/export preferences](https://github.com/FreeCAD/FreeCAD-documentation/blob/main/wiki/Import_Export_Preferences.md) describe STEP import structure options, including assembly-per-document and object-per-document, link groups, instance names and compound expansion. Export preferences expose STEP length units and AP203/AP214 selection. The page also says a single-object placement may be encoded in geometry after reimport. These are UI preferences in the archived documentation repository, not proof of a particular FreeCAD API or a lossless round trip.
3. **Documented STEP APIs (DOM-38, DOM-39):** the official [OCCT STEPCAFControl_Reader reference](https://dev.opencascade.org/doc/refman/html/class_s_t_e_p_c_a_f_control___reader.html) documents import of assembly shapes, names and colors into a DECAF document, with transfers of one or all roots and an option to compose results as an assembly. The [STEPCAFControl_Writer reference](https://dev.opencascade.org/doc/refman/html/class_s_t_e_p_c_a_f_control___writer.html) documents transfer of documents, labels and root-assembly sequences to STEP, with names and colors configurable. Its unit preparation reads a root-label length unit or falls back to the Cascade length unit. Both requested dev.opencascade.org URLs redirected to the OCCT3D-hosted OCCT 8.0.1 manual. These references establish documented API features; they do not establish that FreeCAD embeds or exposes a particular OCCT build, or that names, repeated occurrences, hierarchy, units and geometry survive a real round trip.
4. **Asset identity and license (DOM-06, DOM-26):** [KiCad's library license](https://www.kicad.org/libraries/license/) states CC-BY-SA 4.0 with an exception for designs and generated files using library data; redistributing library data as a collection retains its license and attribution. The [MuJoCo Menagerie catalogue](https://github.com/google-deepmind/mujoco_menagerie/blob/main/README.md) lists licenses by model and directs readers to each model directory's `LICENSE` for XML and asset terms, while its top-level Apache-2.0 notice covers remaining repository content. A reusable-asset record therefore needs the item/model directory and exact license source, separate from the CAD application's software license. KiCad's collection terms do not determine third-party model terms, and Menagerie's root license does not assign one blanket license to model assets.

## OCS source boundary

The existing [point-02 software review](/home/leo/projects/3dmodeling/research/action-audit/reviews/point-02-software.md) describes the locally inspected OCS STEP writer: it collects triangles from input meshes into one faceted shell/solid/representation, emits an SI millimetre unit entity without attaching it to the geometric representation context, rounds coordinates to six decimal places and skips triangles with invalid indices. This is source-code inspection, not an executed export. The OCCT references describe richer document and assembly operations; they do not change the OCS writer's source-level behavior. Keep the proposed FreeCAD/OCCT adapter separate from the OCS mesh-to-STEP writer until a versioned import/export fixture establishes its inputs, geometry representation, unit interpretation, occurrence structure and checks.
