## 1. Findings for the point-06 definition

1. **Robot structure needs explicit rigid-link and joint records.** An assembly occurrence, a rigid link and a mesh asset have different identities. DOM-31 authors an assembly graph and joint set from the CAD assembly, measured interfaces and model brief. DOM-37 creates those records for a sourced component. DOM-08 consumes the authored joint set and measurements to create the robot assembly. Preserve the occurrence-to-link map, fixed attachments, moving relations and every joint's parent, child, origin, axis, type, limit values/units and source. The [original domain operations](../../workflows/domain-paths.json) and [component-to-link dossier](../../workflows/details/dom-r02.md) establish these transitions.
2. **Fixed connections and moving joints require different interpretations.** Group parts that move rigidly together using source connection evidence. Retain their component occurrences inside the link. A rotationally symmetric surface supplies a candidate geometric axis; the brief, joint documentation and measured interfaces supply motion intent, allowed motion and limit interpretation. Tree/loop classification remains an explicit graph result. A closed-loop candidate receives its own supported representation/constraint route.
3. **Visual, collision and inertial origins need separate maps.** A robot package retains link-to-visual, link-to-collision and link-to-inertial transforms and their source revisions. For mass properties, record kg, COM coordinates with length units, tensor units kg m², reference point and axes, and the measured/manufacturer/calculated status. A source render material has its own appearance role. The [domain/component assessment](../../domains-and-components.md) and [MuJoCo/URDF source summaries](../../sources/round-03/domain-detail-sources.json) support these distinctions.
4. **Building semantics and evaluated geometry have distinct checks.** For IFC, retain schema, project units, entity/GlobalId identity, class, storey containment, property sources, host/void relationships, placements and representation type. For triangles or B-rep, retain the element-to-geometry map and actual extraction settings, including local/world placement and evaluated opening behavior. An opening's visible hole and its `IfcRelVoidsElement` host relation receive separate evidence rows. The [building dossier](../../workflows/details/dom-r01.md) provides the original wall/opening checks.
5. **The site transform is a sourced engineering input.** Preserve the element-local → storey/building/project → site/map transform chain, length conversions, datum and axis directions. Record CRS/map-conversion values and project-north/true-north interpretation from survey/source records. Local model orientation and a geographical assignment retain their individual evidence. Registered [placement and georeference summaries](../../sources/round-03/domain-detail-sources.json) provide the API context.
6. **The existing IFC example supplies a concrete provenance pattern.** The live provenance manifest (`${ENERGY_SIM_ROOT}/data/real-house-ifc/provenance.json`) records `casa-parametric-fixture`, deterministic converted source-part identifiers, source millimetres to IFC metres with multiplier `0.001`, adapter/source hashes and source local-frame preservation. Its opening holes are embedded in wall geometry; its listed semantic error is the absence of a relational `IfcOpeningElement`/`IfcWindow` assembly. Use the recorded identity type, geometric openings and semantic relationships as separate fields in future fixtures.
7. **Collision approximation needs feature-level evidence.** DOM-13's convex pieces can change passages, gaps and contact surfaces. Keep hull-to-source mapping, settings, units/frame and named contact requirements. Compare required passages and contact envelopes as well as aggregate bounds/volume. Its original licence URLs support software rights; the registered CoACD repository supplies algorithm/entrypoint information. The [collision/environment dossier](../../workflows/details/dom-r07.md) and [source summaries](../../sources/round-03/domain-detail-sources.json) retain these source roles.
8. **Domain merges create their own checked revision.** A merge can change rigid grouping, joint interpretation, opening-host correspondence, contact geometry or physical-property dependencies. Preserve branch identities and the source of each selected field. Recheck the merged domain graph, geometry, required features and actual saved consumer artifact. A separate semantic reviewer examines the original evidence and the resulting mappings.

## 8. Proposed validation cases and resource records

Each future validation case retains source files/records, expected associations/measurements, criteria and tool versions before execution. The outcomes below are expected behavior.

1. **Rigid multi-component link plus moving child:** repeated part definitions have distinct occurrences; two occurrences move rigidly together. Expected: retained occurrence identities, explicit rigid grouping and one intended moving relation.
2. **Axis sign and limits:** candidate joint records use different axis/coordinate conventions. Expected: source-linked sign/limit interpretation and matching physical sample poses under each documented mapping.
3. **Same neutral pose, different kinematics:** two candidates coincide at one pose and differ at another declared coordinate. Expected: forward-kinematics comparison detects the affected link/frame while the neutral-pose view retains its actual finding.
4. **Closed kinematic loop:** the source graph contains a loop. Expected: explicit loop report and a supported constraint/representation branch with its own checks.
5. **Visual/collision/inertial origins differ:** source assets use separate local origins and mesh units. Expected: separate transforms, checked scale and source/consumer pose/property correspondence.
6. **Off-centre COM and rotated inertia frame:** source properties apply to a named component configuration. Expected: preserved raw tensor/reference frame, documented transform/aggregation and correct consumer inertial mapping.
7. **Mixed-material or hollow source:** a single exterior display mesh is paired with component/material or measured-property evidence. Expected: selected physical-property branch and exact applicability recorded with its calculation checks.
8. **Required passage lost by convex approximation:** a source opening remains visible in the display mesh while a hull fills it. Expected: local passage/envelope and contact fixture detects the changed geometry.
9. **IFC hole with and without relational opening:** geometric holes have different semantic records. Expected: geometry comparison and host/void/filling relationship comparison report their own results.
10. **Nested IFC placement and project/site frame:** local/storey/site transforms and units differ from target display/world coordinates. Expected: one explicit transform chain, correct control points, no duplicate transform application and preserved element identity.
11. **Library definition with several building instances:** one component is inserted at different storeys/orientations. Expected: one source pin, separate IFC occurrence identities, correct placements/containment and rights linkage.
12. **IFC triangles and B-rep:** identical source elements use two extraction routes. Expected: actual representation/face types, evaluated openings and element map retained, with required-feature differences measured per route.
13. **CAD geometry replacement in a model seed:** visual geometry changes under an existing MJCF body tree. Expected: retained joint/actuator/sensor identity, explicit geometry/frame map and rechecked physical/contact dependencies.
14. **Scene with camera-only input:** the input contains camera evidence. Expected: camera-bearing scene and its actual object manifest; geometry coverage is evaluated against that input contract.
15. **Merged domain revision:** sketch/context, precision, semantic and physical branches pass their own scoped checks, then combine. Expected: new merged identity and fresh feature/frame/graph/property/consumer checks plus independent source-semantic review.
16. **Fabrication revision mismatch:** drawing annotations refer to an earlier feature revision. Expected: the dimension-to-feature/revision comparison identifies that exact mismatched feature and output.
17. **Source-change and interruption:** an asset frame or physical value changes while a saved earlier artifact remains pinned; a subsequent export loses its response. Expected: targeted dependency invalidation and operation-state recovery with a receipt for the actual output.
