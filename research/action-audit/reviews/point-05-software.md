Date: 2026-11-12. Scope: CAD-11, CAD-02B, REC-01, REC-02, REC-07, REC-08, REC-09, REC-12, REC-13, REC-14, REC-15, REC-16, DOM-19 and DOM-23. No external research, image processing, calibration, registration, geometry, installation or CAD operation was performed. A read-only Python command extracted operation records from JSON. ## Findings for procedure design

1. **Camera pose convention:** The recorded [OpenCV PnP source](https://docs.opencv.org/4.x/d5/d1f/calib3d_solvePnP.html) describes `solvePnP` as estimating object-to-camera rotation and translation from 3D/2D pairs, camera intrinsics and distortion. OpenCV camera axes are X right, Y down and Z forward. Name the matrix `T_camera_object`, declare whether pixel coordinates are raw or undistorted and retain crop/resize and pixel-origin conventions. The inverse is needed for a camera-to-object ray. [Calibration tutorial](https://docs.opencv.org/4.x/dc/dbb/tutorial_py_calibration.html) supports corresponding calibration-target points and images; its target size supplies a length reference to that pose problem, not scale for an unrelated reconstruction.
2. **Source and target are separate:** REC-07 and REC-08 correctly define source-cloud and target-cloud `input_roles` in [reconstruction operations](../../workflows/reconstruction-paths.json). The recorded [Open3D ICP source](https://www.open3d.org/docs/latest/tutorial/pipelines/icp_registration.html) uses source, target, distance threshold and source-to-target initialization; it reports transformation, fitness and inlier RMSE. Fitness is dimensionless and inlier RMSE is in cloud length units. The input cloud's own multi-frame registration, metric scale and control checks must be established before engineering interpretation; its transform into a separate target frame is an output of REC-07/08, not an assumed prerequisite.
3. **A fit is sampled evidence:** [Open3D point-cloud documentation](https://www.open3d.org/docs/latest/tutorial/geometry/pointcloud.html) is registered for `segment_plane`, `cluster_dbscan`, normal estimation and inlier indices. Plane fitting and clustering do not establish a cylinder-fitting API, physical feature type or design intent. Cylinder/axis fitting needs a specified separately evidenced fitter and identifiability checks; a short partial arc can have a small residual with a poorly determined radius.
4. **CAD and scan registration:** REC-12's photo route may produce a camera solution and CAD-to-camera pose; its point-cloud/mesh route produces a source-to-target registration and must not fabricate camera poses. The existing [REC-R09 dossier](../../workflows/details/rec-r09.md) identifies CAD tessellation, point sampling and datum/revision evidence; sample density, facet error, target geometry and coverage must accompany residuals.
5. **Screen ray and meaning:** [REC-R07](../../workflows/details/rec-r07.md) records a Blender `Scene.ray_cast` example using evaluated scene and world-space origin/direction, but the [source register](../../sources/source-register.md#src-c98a5b96ef0d) states the online API page was search-indexed and direct retrieval returned HTTP 402; verify exact signature in the selected Blender version. The screen ray's intersection can be valid for the selected mesh and camera yet differ from the physical surface or intended sketch. Reprojection into the same originating view checks mapping consistency, not independent geometry accuracy.
6. **Parametric history:** REC-14 describes editable feature history through the OCS workflow, but OCS control notes (`${CODEX_HOME}/skills/ocs-engineering/references/ocs-control.md`) say a parametric feature tree was not established. A supported FreeCAD/code-CAD backend may supply a separately evidenced parametric source; an OCS native body and an executable feature source need separate output labels. The local model contract (`${CODEX_HOME}/skills/ocs-engineering/references/model-contract.md`) checks caller-supplied point/axis/plane relations; it does not independently query CAD solids or authenticate evidence.

## Proposed helpers and responsibilities

All helpers below are proposals. Each input and output has source ID/hash, revision, frame, axes, units, evidence class, tool/version, settings, actor and check records. The agent interprets feature identity, matches, intended use and competing hypotheses; software executes declared transformations, fits and comparisons. User decisions resolve missing engineering intent and contradictions that affect construction.

1. **REC-01 — Calibrate camera intrinsics and distortion:** `calibrate_camera(target_images, target_geometry, camera_model, detector_settings) -> intrinsics, distortion, per_view_poses, report`. Retain image sizes and preprocessing, target square/feature coordinates with units, detector points, chosen model/flags and training/held-out split. Software reports detection failures, global and per-view reprojection residual distributions and held-out checks; agent reviews target identity, image coverage and camera/lens consistency. Insufficient view diversity or changed focus/resolution creates an unresolved calibration boundary.
2. **REC-02 — Solve camera pose:** `solve_pose(camera, pairs_3d_2d, solver_settings, withheld_pairs) -> T_camera_object, candidate_poses, report`. Record feature IDs, 3D frame/units, 2D raw or undistorted pixel mapping, flags, robust threshold/iterations, inliers and pose alternatives. Software checks input validity, positive depth/visibility, per-point reprojection and withheld controls; agent reviews correspondences and planar/symmetric ambiguity. Do not apply lens distortion twice or apply the inverse pose as the forward pose.
3. **CAD-02B — Calibrate camera poses from photographs and controls:** `calibrate_and_solve(photo_set, calibration_or_targets, control_pairs) -> camera_solution, lineage`. Compose REC-01 and REC-02 only for matching camera model/resolution and per-photo control evidence; preserve each image ID, calibration revision, object frame, pose and withheld checks. Agent selects known controls and diagnoses inconsistent images; software blocks pose-dependent work for images lacking sufficient matching controls.
4. **REC-07 — Estimate coarse point-cloud transform:** `coarse_register(source_cloud, target_cloud, initial_controls, config) -> T_target_source, hypotheses, report`. Inputs have distinct IDs, units, frame definitions, internal acquisition/registration and independent metric controls. Software records downsample voxel size, normal and FPFH neighborhoods, feature correspondence IDs, RANSAC distance/edge/normal checks, seed and inlier set. Agent identifies overlap, symmetry, candidate poses and sufficient independent target references. If relative scale is unresolved, treat similarity-scale estimation as a distinct sourced method and record scale evidence; do not silently treat rigid ICP as scale calibration.
5. **REC-08 — Refine registration and compare surfaces:** `refine_registration(source, target, T_target_source_initial, estimator, thresholds, regions) -> transform, residual_report`. Point-to-plane mode requires target normals as defined by the selected adapter; record normal estimation, threshold units, sampling, iteration and convergence. Report source/target coverage, unmatched regions, inlier count, dimensionless fitness, length-unit RMSE, regional residual quantiles and withheld control errors. Agent reviews symmetry, density imbalance, repeated geometry and non-overlap; local convergence is not unique-pose evidence.
6. **REC-09 — Segment and fit sampled features:** `segment_and_fit(metric_registered_cloud, region, model, fit_config) -> inlier_indices, coefficients, residuals, observability_report`. Preserve raw/filtered indices and each filter; specify plane `segment_plane`/DBSCAN parameters or a separately documented cylinder fitter. Record noise, coverage/arc span, outliers, parameter uncertainty or sensitivity and held-out points. Agent determines whether the detected surface plausibly belongs to one feature and retains alternative interpretations. Small inlier residual and high feature certainty are separate statements.
7. **CAD-11 — Fit analytic features to scans or image-derived clouds:** `fit_analytic(source_geometry, registered_frame, independent_controls, feature_intent) -> feature_candidates, fit_report` consumes a cloud/mesh with metric scale, internal registration and independent scale/frame checks. For a depth-frame input, first obtain a separately recorded calibrated, registered cloud; do not fit pixels as spatial coordinates. Software carries regional point membership, fitted plane/cylinder/axis, units, error distributions and source quality; agent selects feature type and reviews incomplete coverage. Feed candidate dimensions to CAD only as labeled fitted estimates.
8. **REC-12 — Register CAD to photos or scan:** `register_cad(cad_revision, source_observation, datum_controls, adapter) -> registration_record, comparisons`. Pin native geometry, units, component/frame and tessellation/landmark mapping. For photo, pair CAD 3D feature IDs and image 2D IDs and use the calibrated PnP route. For scan, sample a labeled CAD derivative, then compute explicit `T_target_source` and compare scan coverage, sample spacing and approximation error. Agent reviews landmark correspondence and alternative poses; withheld features and independent dimensions validate each route. Preserve original CAD and sensor evidence.
9. **REC-13 — Anchor screen sketch to 3D surface:** `raycast_strokes(image_strokes, camera_solution, scene_revision, selected_target, hit_policy) -> anchor_candidates, misses, report`. Map original pixel through preprocessing and inverse distortion to camera ray; transform origin/direction to target query frame; retain object ID, evaluated mesh hash, triangle/face ID, hit location/normal, distance, visibility and transformation. Record miss, multiple surfaces, backface/occlusion and near-tangent uncertainty. Software reprojects anchors as a mapping check; agent selects the intended surface and whether result is trace, projected curve or datum-plane sketch. Independent controls and source geometry validation determine physical evidence.
10. **REC-14 — Remodel segmented scan as parametric CAD:** `remodel(fit_candidates, independent_dimensions, feature_decisions, backend) -> source_or_native, shape, evidence_map`. Use declared feature values/units/frame and retain measured, drawing, fit and assumed values separately. A parametric output requires a demonstrated parametric backend and retained script or native feature document; an OCS body uses its observed native representation. Software verifies revision/readback, solid topology and feature dimensions plus withheld surface regions; agent reviews visible coverage, feature semantics and hidden geometry.
11. **REC-15 — Reconcile scan and dimensioned drawing:** `compare_evidence(scan_revision, drawing_revision, common_datums, controls) -> aligned_claims, contradictions, report`. Calibrate drawing and scan separately, identify matching feature/datum IDs, fit a transform using designated controls and reserve others. Preserve drawing nominal and allowance, scan measurement/fit and each uncertainty; do not average conflicts without an explicit rule. Software computes per-feature directional distances and coverage; agent considers revisions, manufactured variation, measurement error or a wrong match.
12. **REC-16 — Iterate CAD edits against evidence:** `compare_revision(cad_revision, immutable_scan, transform, regions, checks) -> report` and a separate authorized `edit_and_readback` proposal retain versioned revisions and stable comparison setup. Software reads back geometry, measures named interfaces and regional max/RMS/quantiles, retains failed results and verifies topology; agent selects bounded edit and diagnoses whether improvements actually apply to the same feature/coverage. Changing the transform or scan creates a new comparison baseline and invalidates direct before/after claims.
13. **DOM-19 — Register scan to building frame:** `register_building(scan, ifc_revision, survey_controls, frame_chain) -> T_building_scan, aligned_cloud, report`. Explicitly resolve sensor/scan frame, IFC project units, local-to-building placement, axis convention, CRS/map and vertical datum where used. Software records paired control IDs, transformations, rigid versus similarity scale, residuals and withheld checks; agent reviews datum meaning, overlap, building changes and semantic component selection. A single datum leaves rotations and possibly scale underdetermined; distributed controls must support the chosen transform.
14. **DOM-23 — Scan or mesh to parametric CAD remodeling:** `build_parametric_model(registered_evidence, brief, feature_map, backend) -> parametric_source, cad_solid, verification` combines checked metric source, named interfaces, source-linked inputs and explicit feature intent. Software verifies supported output, source revision, body/feature counts, validity, readback and withheld scan/interface measurements; agent compares analytic vs sampled shape, unresolved hidden features and function. Preserve raw source, transforms, fit parameters and alternatives; an inferred mesh or facet conversion does not itself create a parametric feature history.

## Frames, uncertainty and checks

1. Use `p_target = T_target_source p_source` with explicit matrix convention, units, coordinate handedness and named frame IDs. Preserve inverse, component transforms, scale separately from rigid pose and every source/target revision. Screen pixel origin, resize/crop, camera axes, distortion state and camera-to-world conversion must be recorded. IFC local placements and map CRS form a separate documented chain. A transform with an unsupported, unknown or singular mapping blocks dependent coordinates.
2. Distinguish calibrated sensor observations, registration estimates, dimensional drawings, fitted primitives, calculated ray hits, assumed hidden surfaces and intended design dimensions. Record source uncertainty, engineering allowance, fit noise, discretization/tessellation error and computational comparison threshold separately for each feature. Propagate relevant calibration, registration, sampling and fit effects to a feature uncertainty or report the supported uncertainty estimate and its method; a low optimizer residual alone supplies no complete uncertainty budget.
3. Validate source cloud scale and internal registration with independent length/point checks, coverage, calibration and drift records. Registration to a separate target requires both named clouds and `T_target_source`; compare held-out controls, spatially distributed regional errors and non-overlap. ICP fitness and RMSE depend on threshold, density and selected inlier set; report them with settings and inspect alternate symmetric or degenerate poses. Disparate sampling may bias nearest-neighbor distances. Record whether distances are point-to-point, point-to-plane or point-to-surface and their direction.
4. A screen ray can correctly hit an inaccurate, incomplete or wrong object; a reprojected hit can return to its originating pixel by construction. Report scene/object source validity, visibility, near-tangent uncertainty and independent dimensions separately. Analytic radius/axis estimates require sufficient angular/longitudinal coverage and stable fit under reasonable data/threshold variation; no unobserved depth is promoted to measured geometry.

## Failure and resumption

Keep raw photos, sensor data, source clouds, CAD/drawings, transforms, matched and rejected IDs, model revisions, failed fits and reports. Report exact operation, source hashes, settings, failure and affected feature/region; no downstream dependent result is marked passed. Degenerate controls, wrong lens/resolution, symmetric poses, low overlap, failed normals, unobservable radius, unit/CRS conflict or insufficient independent controls require a bounded new interpretation, new evidence or alternate supported method. A changed pose, calibration, scale, source geometry or CAD revision invalidates dependent rays, fits and comparisons. After an uncertain OCS write, query the same request ID and completed batch steps before any retry.

## Meaningful future tests

1. **Camera:** Synthetic camera/target with known intrinsics, distortion, image size and poses, held-out image points; compare recovered pose using explicit object-to-camera direction and `projectPoints`. Include cropped/resized image, unit conversion, wrong correspondence, planar ambiguous solutions, incorrect distortion and positive-depth failures. Confirm an inverse-pose error fails independent controls.
2. **Cloud registration:** Known rigid transform with separate source/target IDs, calibrated scale, withheld distributed fiducials and partial overlap; test point-to-point and point-to-plane with valid normals. Include symmetry, repeated plane, different densities, wrong initialization, bad normals, outliers and metre/millimetre mismatch. Show low inlier RMSE can accompany a wrong pose; block a claim of metric accuracy when held-out controls fail.
3. **Feature identifiability:** Plane plus full cylinder and narrow partial arc with noise/outliers; compare fitted parameters, region membership, sensitivity and withheld surface errors against known synthetic truth. A partial arc that fits well but leaves radius uncertain must remain unresolved. Test wrong segmentation that merges two adjacent surfaces.
4. **Ray hit:** A calibrated image and scene with transformed object, two occluding surfaces, missing ray and grazing ray. Test actual selected adapter's coordinate convention, source triangle mapping, hit/miss and world transform, camera inverse, multiple hits and reprojected pixels. Perturb mesh or camera while keeping self-reprojection consistent: an independent 3D control must expose the geometry change.
5. **CAD/drawing/building:** A CAD part and scan with independent drawing dimensions, a conflicting drawing revision, known datum transform, and an IFC local-placement chain with explicit unit conversion and map frame. Verify distinct claims, semantic IDs, transform directions, preserved disagreements and held-out interface sizes; missing CRS or a single datum cannot silently define an unconstrained transform. Reopen the actual native/export artifact in a separate supported consumer when conversion is authorized.
6. **Recovery:** Interrupt registration, segmentation and CAD edits, then change one input hash, calibration or transform. Verify dependency invalidation, retained partial reports and fixed comparison baseline. Query uncertain operation state before retry; a failed Boolean, stale revision or unavailable measurement produces a finding instead of a pass.
