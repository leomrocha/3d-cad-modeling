## Findings for procedure design

1. **Rectification controls:** [CAD-R02](../../workflows/details/cad-r02.md) records `cv2.getPerspectiveTransform` with four point pairs and `cv2.warpPerspective`. A general planar projective transform requires sufficient corresponding image and plane coordinates in general position; four points on each plane with no three collinear form a minimal case. One known length supplies scale only under an independently justified restricted model such as a front-parallel similarity transform; a length alone does not determine a general perspective transform. Four precisely fitted controls do not independently validate the transform: reserve separate points or lengths for verification. A plane transform cannot recover 3D depth or correct unmodelled lens distortion and nonplanar paper deformation.
2. **OCR:** [Tesseract command documentation](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html) is recorded as documenting TSV hierarchy, word boxes, confidence and text. These are OCR candidates. Decimal separators, diameter/radius and tolerance glyphs, units, dimension-line endpoints and feature associations require source-pixel review. An OCR word box is not itself a verified glyph segmentation or association.
3. **Vector candidates:** [OpenCV shape documentation](https://docs.opencv.org/4.13.0/d3/dc0/group__imgproc__shape.html) and [feature documentation](https://docs.opencv.org/4.13.0/dd/d1a/group__imgproc__feature.html) are recorded for `findContours`, `approxPolyDP` and `HoughLinesP`. Contours follow raster regions, Hough segments are line candidates, and simplification changes paths under a pixel-space criterion; none provides engineering feature semantics or a true arc by itself. Potrace is a potential bitmap-to-path alternative; no Potrace source or license was found in the inspected project records, so its exact outputs, version and availability need separate source evidence before an API claim.
4. **Geometry and semantics:** CAD-05 produces a proposed wall/opening graph; CAD-17 uses a reviewed graph and independently supplied vertical dimensions to construct candidate wall/opening geometry; DOM-18 authors IFC classes and relationships. These are three distinct transitions. [CAD-R03](../../workflows/details/cad-r03.md) classifies the cited floor-plan papers as research methods, with no asserted general-purpose installed CLI. A closed wall outline or solid does not establish IFC spatial containment, opening relations or element classification.
5. **View reconstruction:** [CAD-R09](../../workflows/details/cad-r09.md) records orthographic reconstruction papers as research references, with no general-purpose executable established. Registration requires at least two identified views with their scale, axes, projection convention and datum. Reprojection agreement cannot uniquely establish hidden geometry: retain competing correspondence and 3D hypotheses, and distinguish source-observed from inferred features.
6. **OCS underlay:** OCS API specification (`${OCS_ROOT}/docs/automation/API-SPEC.md`) documents `embed_image` with a position and width, embedded and linked modes, entity queries, measurements and drawing commands. The image command source (`${OCS_ROOT}/src/modules/draw/draw/raster_image.rs`) implements placement and aspect-based sizing; its Enter fallback uses a default width derived from pixel width. That fallback is a display placement, not calibration evidence. No image registration, OCR or semantic recognition is established by those interfaces.

## Proposed helpers and responsibilities

These interfaces describe proposed behavior, not implemented software. Each result carries source image ID/hash, tool/configuration and version, coordinate frame, source locators, evidence status, timestamps and revision. Software performs declared geometry, transformation and consistency checks; an agent interprets marks, associations and alternatives against the original. User-supplied decisions resolve design, units, dimensions and ambiguous intended features when needed.

1. **CAD-02 — Rectify a raster drawing plane:** `rectify(image, control_pairs, plane_frame, output_grid, lens_model?) -> transform_record, rectified_image, residuals`. Record pixel-center convention, point IDs and original pixel coordinates, source and plane values/units, image-to-plane and inverse mappings, crop/rotation/resize composition, output grid, interpolation and valid-image mask. Verify rank/conditioning and reject coincident or degenerate controls; separately check withheld control distances/points and retain their residuals. The agent identifies the common plane and controls, judges distortion/folds and chooses only a supported transform model. Output feeds OCR/vector processing with a reversible locator map; cropped or unmapped pixels are explicitly marked.
2. **CAD-03 — Recognize dimension text:** `extract_text(image_revision, regions, ocr_config) -> raw_tsv, token_candidates, source_maps`. Record recognized words, boxes, confidence, original pixels and mapped polygons after crop/deskew/rectification; retain exact raw output and alternatives. `interpret_dimension(tokens, glyph_evidence, feature_candidates) -> claim_candidates` keeps original string, numeric value, sign, unit, tolerance, glyph and related arrow/extension-line/view IDs. The agent reads actual glyphs and associates each value with named geometry; unresolved candidates remain unresolved. A confidence score is a recognition output, not a source validity or semantic acceptance score.
3. **CAD-04 — Extract raster edges, lines and contours:** `extract_strokes(image_revision, masks, parameters) -> segments, contours, source_overlay, diagnostics` retains raw pixel paths and processed coordinate maps. Label pixel edges, filled-region boundaries and fitted primitives separately, including threshold, line width, simplification and fit residuals. The agent distinguishes profile, centerline, hidden lines, dimensions and annotations and reviews false joins/omissions. If arc/circle fitting is proposed, expose fit inputs and residuals; an approximated polygon is not an analytic arc. Feed reviewed vectors to a profile or graph builder with per-feature tolerances.
4. **CAD-05 — Convert floor-plan candidates to wall/opening graph:** `propose_plan_graph(vectors, source_dimensions, conventions) -> graph_candidates, evidence_map, checks`. Nodes carry ID and pixel/plane position; walls carry centerline/edge convention, thickness source and endpoints; openings carry host-wall ID, offset/span and symbol evidence. Preserve disconnected alternatives, labels, measured and inferred claims. Software checks endpoint attachment, intersections, graph consistency and supplied lengths; agent reviews symbol meanings, actual wall continuities and uncertain junctions. A visually closed room is a proposed graph relationship until supported by the source.
5. **CAD-06 — Register orthographic views:** `register_views(view_bundle, projection_convention, scale_datum, correspondences) -> view_transforms, correspondence_candidates, residuals`. Retain per-view plane axes, pixel-to-vector transforms, first/third-angle convention, projection directions, independent dimensions and competing edge IDs. Software compares corresponding projected coordinates and dimensions, reports contradictory scales or unmatched/ambiguous edges, and retains all hypotheses. Agent selects views and reviews occlusion, line types and correspondences. A 2D line supplies constraints on 3D geometry, not a unique depth for that line.
6. **CAD-07 — Reconstruct candidate 3D geometry:** `construct_candidates(registered_views, correspondences, parameters, representation) -> candidates, provenance_graph, projection_reports`. Use explicit feature directions, topology choices and sourced dimensions; track each face/edge to supporting views or inferred status. Software evaluates projected geometry per view, dimensions, topological validity and requested representation. The agent examines indistinguishable alternatives, occluded surfaces, hidden edges and conflicting dimensions, and requests evidence for unresolved construction. A valid closed body and small reprojection residual are independent results, not proof that hidden features are correct.
7. **DOM-02 — Raster sketch to constrained sketch:** `build_sketch(reviewed_curves, dimension_claims, sketch_frame) -> sketch_revision, solver_and_source_report` maps each original crop and dimension to named geometry and constraints. Software records geometry changes, solver state/degrees of freedom where the backend exposes them, profile closure and residuals against independent source values. The agent checks glyph/feature association, intended curve class and appropriate unconstrained degrees; source conflicts remain visible even if the solver converges. OCS drawing geometry and FreeCAD Sketcher are separate routes with separately observed capabilities.
8. **CAD-17 — Build wall/opening solids:** `build_wall_geometry(reviewed_graph, vertical_parameters, backend) -> component_geometry, construction_ledger, checks`. Inputs require source-linked wall height, thickness convention, floor datum and opening elevations/dimensions; preserve the original graph and each wall/opening ID. Software constructs and checks wall/opening geometry, interfaces, dimensions and plan projection; agent checks topology and that dimensions describe the intended element. A missing elevation blocks only the dependent 3D element or remains a labeled parameter; do not derive it from plan pixels. Output is geometry and graph mapping, with no IFC classification implied.
9. **DOM-18 — Raster floor plan to IFC building:** `author_ifc(reviewed_graph, semantic_decisions, building_brief, project_units, selected_assets) -> ifc, element_source_map, validation_report`. Software assigns explicitly supplied project/storey hierarchy, class, placement, geometry and opening/host relation through the versioned IFC API and retains links to source pixels, graph and selected assets. Check schema, GlobalId uniqueness, containment, opening host relations, units/placements, geometry and declared quantities; inspect the output in an independent consumer. Agent reviews class/element meaning, storey membership and dimensions against the source; no semantic class, floor elevation or object relationship is inferred silently from a closed loop.

## Tolerances, transform and provenance

1. Give every relevant feature and measurement a nominal value, unit, source locator, plane/frame and status: source claim, measurement, image estimate, calculation, inference or user decision. Record engineering allowance, source measurement uncertainty and computation/fit threshold separately. Derive or cite each threshold for that feature and intended use; no global pixel or millimetre tolerance is adopted here.
2. Propagate coordinate transforms and control uncertainty through to the measured feature; a pixel displacement can correspond to different physical distances across a perspective image. Preserve original pixels and mappings through every crop, rescale, rotation and warp. An OCR rectangle mapped through a projective transform becomes a polygon; retain its actual mapped corners rather than assuming an unchanged axis-aligned box. Record interpolation and any regions outside the inverse map.
3. Compare projective controls to withheld independent controls, line/vector residuals to original pixels, sketch constraints to source values, geometry to reviewed graph and IFC semantics to explicit relationships. These are separate checks bound to artifact hashes and revisions. Shared pixels or shared OCR candidates across reviewers can yield correlated errors; agreement alone does not validate the source interpretation.

## Proposed failure and resume behavior

Retain the original image, controls, prior revisions, raw OCR output, candidate vectors and diagnostic overlays. Log stage, input hashes, tool/version/configuration, exact error, partial result and dependent feature IDs. Degenerate transforms, conflicting units, blurry glyphs, open/merged contours, ambiguous view matches, kernel refusal or missing elevation stop the affected transition; independent source regions remain usable. An edited control or source creates a new revision and invalidates dependent OCR locator maps, geometry and checks. After an uncertain OCS mutation, read the operation state under the same request ID and any completed batch steps before a further action.

## Meaningful future tests

1. **Rectification:** synthetic coplanar image with known projective warp, four general-position controls, withheld control points and lengths, plus a front-parallel scale case. Verify both mappings and local physical residuals, including crop/resize composition and bounds. Collinear/duplicate points, wrong control ordering, source distortion and warped paper must trigger a diagnostic or fail independent controls.
2. **Text/association:** fixtures with `8`/`3`, diameter/radius marks, decimal comma/point, asymmetric tolerances, rotated text and crossed extension lines. Verify exact crop-to-original mapping, raw OCR retention, alternative glyphs, numeric units and feature links. Include a plausible high-confidence wrong token and check it remains a candidate until source review.
3. **Vector/graph:** thick and double strokes, touching dimensions, arc/circle, gaps, crossing walls, door and window openings, ambiguous junction and known scale. Compare path-to-pixel residual and feature IDs, graph connectivity, host attachment and independent lengths. Confirm polygon approximation or an overclosed region is reported and no wall/opening type is created from line extraction alone.
4. **Orthographic ambiguity:** front/top/side views with two solids sharing the same visible projections but different occluded features, a first/third-angle mismatch, conflicting dimensions and one missing view. Verify transform convention, retained alternative matches and per-view reprojection; ensure a plausible but wrong hidden feature cannot be marked observed.
5. **Sketch, solid and IFC:** a reviewed wall graph with a door opening, known wall length/thickness/height and datum, plus cases with missing opening height, wrong host and inconsistent scale. Check source-linked sketch constraints, output geometry dimensions and closure, IFC class/storey/host/void relationships and a separate consumer readback. Remove a source value and verify the dependent feature stays blocked or an explicitly labeled parameter; schema success alone does not pass source correspondence.
6. **Resumption:** interrupt after rectification, OCR and geometry stages; change one control and verify only dependent mappings/results are invalidated, prior evidence remains accessible and no duplicate geometry is created after state reconciliation. Record actual tool and host resources only for an executed case.
