## Proposed responsibilities and handoffs

Each software helper below is a proposal, not a delivered program. A reasoning agent chooses and interprets supplied evidence, diagnoses exceptions and presents decisions; software carries out specified deterministic operations and records results. User decisions determine intended component selection, ambiguous units/frames, rights interpretation where needed, placement and export purpose.

1. **DOM-06 — Library asset intake and rights record.** Inputs: original bytes or exact source link, item identity/revision, date, terms and known format. Proposed software hashes available bytes, records path/URL, declared format, acquisition status, per-file rights evidence, source claims and derivative links, and validates required fields and duplicate IDs. Agent associates a license or manufacturer statement with its specific item and identifies unresolved terms; software does not infer permission from a filename or tool license. Output: immutable component and asset record for DOM-26/DOM-38/DOM-07. If rights do not allow the requested copy, retain the source reference with actual access status.
2. **DOM-38 — Import STEP solid into CAD representation.** Inputs: original STEP, asset record, declared target and source unit/frame evidence. Proposed version-pinned adapter inspects schema, imported product tree, unit interpretation, geometry types and import/healing warnings; records file hashes, settings and raw readback; emits a separately identified CAD representation. Agent evaluates item identity, scale against independent dimensions, and whether the representation meets intended use. Unsupported or ambiguous unit, empty geometry or unsupported representation blocks dependent placement until resolved. Any actual conversion requires its separate authorization.
3. **DOM-26 — Version and reuse component revision.** Inputs: stable component ID, source bytes or link, per-file terms and derivative lineage. Proposed software creates immutable content records, pins revision and digest in consuming assemblies, compares hashes, records adapter versions/settings and reports changed inputs or terms. A metadata or rights change has a new record revision even if the geometry digest is unchanged. Agent reviews changes in source, interpretation and reuse conditions. Output: revision-pinned component record for selection and placement. A digest alone cannot encode licensing or assembly meaning.
4. **CAD-12 — Assemble existing CAD or source-library components.** Inputs: base and one or more identified components, source representations, part and occurrence IDs, selected local interface frames, target assembly frame and stated intended use. Proposed software verifies frame/unit types and computes declared transforms, then invokes a selected supported placement API and records each instance, source revision, transform and native handles. Agent interprets interface evidence, selects the explicit mating relation and reviews geometry/remaining uncertainties; a drawing arrangement, constraint-based assembly and visual placement are separate alternatives with distinct capabilities. Output: named assembly representation and occurrence graph for DOM-07 and DOM-39, provided the selected adapter actually supports the intended representation.
5. **DOM-07 — Place reusable component in assembly.** Inputs: target assembly revision/graph, pinned component, measured interface evidence, frames and explicit placement relation. Proposed software calculates the component-to-assembly transform from named frames, checks handedness, scale, finite values and datum residuals, and writes a distinct occurrence and mapping. Agent verifies datum meaning, mating and intended clearance; geometric interference checks use a specifically demonstrated query and exact or approximate representation as appropriate. Identical source revisions can have multiple distinct occurrence IDs. Output: new assembly revision, transform evidence and check report.
6. **DOM-39 — Export STEP assembly.** Inputs: assembly revision and occurrence graph, source units/frames, target schema and purpose, adapter/version/settings. Proposed adapter exports a new file and a field-level preservation/loss report including names, repeated instances, relative placements, unit handling, solid/surface/mesh representation, hierarchy and constraints/history. Reopen through a separately selected consumer and compare source and output using tolerances tied to the corresponding source evidence. If the output cannot represent or preserve the requested structure, report the specific loss and keep source assembly and mapping; per-part exports with a sidecar occurrence graph are an alternative proposal. No adapter is selected by this review.

## Representation and evidence boundaries

1. A native CAD assembly can contain definitions, repeated occurrences, placements, constraints and feature history. A STEP file's usable structure depends on source, schema, exporter and importer. Record the actual names/tree, transforms, geometry type, units and warnings at both boundaries; evaluate preserved and lost fields individually. Compare interface dimensions and transforms alongside bounds and part count, because matching envelopes alone cannot demonstrate correct repeated instances or topology.
2. Tessellation produces a polygonal surface approximation. It can change curved surfaces, hole edges and connectivity; a mesh or faceted STEP result cannot by itself recover native analytic geometry, parameter history or assembly constraints. Keep source CAD and an explicit mesh-to-component mapping with local frame, unit/scale, tessellation parameters and measured error where available. Review watertightness, orientation and continuity for the intended operation; a rendered surface alone cannot demonstrate a closed valid solid.
3. The OCS STEP writer's fixed unit entity, flattened mesh collection and independently emitted triangle edges make a unit/assembly/topology test essential before a future user relies on its result. The source labels the result a closed shell and manifold solid; those labels do not establish geometric closure or a valid manifold in a receiving application. The writer also rounds coordinates, so source precision and feature tolerance must govern acceptance.
4. Units, coordinate axes, origin and handedness are independent of part identity and geometry type. Record source and target frames, explicit scale and transform, interpretation evidence and any reversal. A sidecar carries these claims where the chosen format/adapter does not retain them; the file and sidecar have separate hashes and revisions.

## Proposed failure and resumption

Preserve original source and completed independent records. Report the artifact hash, source revision, stage, adapter/version/settings, exact error, partial output, affected occurrence IDs and checks; suspend only dependent operations. An altered source creates a new revision and invalidates affected geometry, mappings and checks. For a timed-out OCS mutation, inspect the operation using its original request ID and completed batch steps before deciding whether another action is needed. A failed import or export retains the output for diagnosis and cannot be promoted to a verified artifact.

## Meaningful future tests

1. **Identity and rights:** Fixtures for identical bytes under distinct item IDs, changed bytes under one item ID, changed license with unchanged bytes, missing terms and multiple derived assets. Verify independent hashes, revision pins, rights evidence and lossless lineage; confirm missing terms produce a specific unresolved finding.
2. **Units and frames:** A source fixture with independently known reference lengths and rotated, translated named frames, plus metre/millimetre and handedness variants. Verify transforms, interface residuals and component identities after round-trip against declared tolerances. Unitless and contradictory unit evidence must produce an explicit unresolved result.
3. **Assembly:** One nested assembly with two occurrences of the same part and a distinct third part, nonidentity rotations/translations and identifiable interfaces. Reopen in an independent consumer; compare definition and occurrence counts, names where representable, hierarchy, relative poses and checks. Detect flattening even when global bounds match.
4. **Geometry and topology:** A sourced analytic cylinder with a through-hole and a multi-solid assembly, plus a deliberately open mesh and a degenerate triangle. Compare geometry type, valid closed topology, connected components, selected interfaces, volume where meaningful and approximation error with per-feature tolerances. A faceted cylinder must be reported as faceted; a `MANIFOLD_SOLID_BREP` label alone is insufficient evidence. Test six-decimal rounding and invalid mesh indices explicitly for the inspected OCS writer.
5. **Recovery and reproducibility:** Exercise malformed or unsupported STEP, failed save, interrupted sequential batch and changed input between attempts. Verify retained originals/partial outputs, operation identity and state, no duplicate occurrence after retry, invalidation of affected checks, and versioned reports. Runtime measurements of CPU, memory, storage and elapsed time require a named fixture and actual run.
