## Recommendations

1. Keep OpenCADStudio (OCS) as the baseline for the existing workflow, native DWG/DXF drafting and MCP-driven drawing operations. The already installed `ocs-engineering` skill supplies unit/frame contracts, session inspection, revision-aware edits, geometric checks and verified-save guidance; the user reports partial runtime success. The local solid kernel offers solid operations, while the STEP exporter consumes tessellated meshes and emits faceted STEP geometry. Preserve OCS as the drawing/model starting point and validate each geometry path against the needed output.
2. Consider FreeCAD as a complementary engineering CAD backend when editable constrained sketches and feature history are required. Its Sketcher, Part Design feature tree, Python API, B-rep objects and STEP exchange support that use. Keep the native `.FCStd` document and scripts as the editable source; treat STEP as geometry exchange and STL/3MF as tessellated outputs.
3. Use build123d or CadQuery for dimensioned, repeatable part families when source code is a useful model history. Both produce OCCT B-rep geometry and STEP; the Python source is the parametric record and neutral exports do not retain that script history. build123d is more explicitly builder/algebraic and supports sketches and assemblies; CadQuery has a mature Workplane API and direct DXF profile import/export.
4. Use OpenSCAD for explicit parameter-driven CSG parts, 2D profile extrusion and fast code-defined variants. Its tree/source is editable; mesh export is not an editable B-rep feature tree. Use Blender for meshes, scanned/reconstructed scenes, visualization and procedural assets, not dimension-critical solid CAD unless a separate CAD kernel checks and exchanges its output.
5. Add project skills that establish a requirements-to-geometry evidence contract and a validated FreeCAD workflow. Adapt existing FreeCAD/OpenSCAD skills as procedural references after audit. OCS already has native MCP support and local project docs; its strongest integration is application-provided rather than a third-party skill.

## Model representations and workflow boundaries

| Representation | Meaning | Typical editable source | Typical outputs |
|---|---|---|---|
| Constrained sketch | 2D lines/arcs with geometric and dimensional constraints | FreeCAD Sketcher; SolveSpace; code-based sketch definitions | DXF/SVG for drawing exchange; profile consumed by features |
| Parametric feature model | Ordered construction operations with parameters and dependencies | FreeCAD document tree; CadQuery/build123d/OpenSCAD source | Native source plus STEP/BREP and optionally STL/3MF |
| B-rep solid | Exact faces/edges/vertices bounded by analytic or spline surfaces | OCCT-based model; FreeCAD Part object | STEP/IGES/BREP; tessellated view/print export |
| Mesh | Vertices and polygon faces approximating surfaces | Blender mesh datablock; scan reconstruction; imported STL | STL/OBJ/PLY/3MF/glTF depending tool |
| Scene | Objects, transforms, cameras, materials, lights and sometimes meshes | Blender `.blend` and Python | Render/video/scene interchange; geometry exchange loses scene semantics |
| Drawing | 2D entities, layers, blocks, annotation and dimensions | DWG/DXF/SVG or application-native drawing | PDF/plot or 2D exchange |

“Editable” therefore needs an explicit target: editable dimensions and feature history, editable exact solid faces, editable polygon mesh, or editable scene graph. STEP preserves geometric B-rep and often assembly/name metadata but generally does not recreate the originating application's feature tree. STL is a triangle mesh and cannot carry design constraints or feature history. DXF/SVG are 2D drawing/profile inputs; importing them requires units, layer/entity filtering, closure checks, self-intersection checks and a declared sketch plane before extrusion or other solid construction.

## Tool assessment

### OpenCADStudio

Observed local source facts (checkout version `2026.41.0`; parent reports inspected Git HEAD `abad1b904577f4ea9d6d826c7143cad1eb5560bd`, clean): README describes desktop/browser technical drawing, layout and solid modeling; native DWG/DXF; primitives, extrusion, revolve, sweep, loft, boolean operations and ACIS tessellation. Its STEP AP203 entry is explicitly “Export 3D mesh data.” Inspection of `src/io/step.rs` confirms `build_step` consumes tessellated `MeshModels` and writes planar triangular faces as `CLOSED_SHELL` / `MANIFOLD_SOLID_BREP`. The STEP extension and entity names therefore do not establish analytic surface preservation; this route exports faceted mesh-derived geometry. The README exposes an MCP endpoint using `OpenCADStudio --mcp`; it launches/attaches to the desktop editor and offers drawing state, entity, command, property, measurement, spatial relationship, history and operation inspection, plus mutation and verified-save/audit operations. It is local application automation, not a hosted AI service. Any connected AI model remains a separate client/service choice. No OCS runtime command was exercised in this research. The user reports that the installed local `ocs-engineering` skill has already been used with partial success; this is a user-reported runtime outcome, separate from source inspection. The local project `LICENSE` begins `GNU GENERAL PUBLIC LICENSE, Version 3, 29 June 2007` (GPL-3.0); it is not AGPL.

The local `docs/cadkernel-body-path.md` and implementation say kernel solid bodies are supported through primitives, transforms, profile regions/surfaces, extrusions, revolves/sweeps/lofts and booleans. This is kernel-body geometry, not by itself evidence of feature-history editing like FreeCAD Part Design. Existing code explicitly notes that regenerated boolean bodies clear `history_handle`; implementation test evidence covers app kernel serialization and DWG/DXF reopen, while its note says interoperability cannot be established by that roundtrip alone. The STEP route exports a tessellation as faceted STEP entities. OCS scripting also has an embedded RustPython plugin, declared GPL-3.0-only, API v7, with release-time ABI metadata; Python plugin execution and feature support depend on that plugin build. MCP avoids Python/package-manager dependencies for application automation.

License observed locally: project `LICENSE` begins with GNU Affero General Public License version 3; source dependencies have their own licences. Primary sources: [OCS repository](https://github.com/HakanSeven12/OpenCADStudio), [local project README](https://github.com/HakanSeven12/OpenCADStudio/blob/main/README.md), [MCP automation guide](https://github.com/HakanSeven12/OpenCADStudio/blob/main/docs/automation/README.md), [kernel body path note](https://github.com/HakanSeven12/OpenCADStudio/blob/main/docs/cadkernel-body-path.md), [Python plugin declaration](https://github.com/HakanSeven12/OpenCADStudio/blob/main/plugins/opencad-python/plugin.toml). Local checkout was inspected rather than fetched from those URLs; source date for this report is 2026-11-12.

Fit: strong for text-driven/agent-driven drafting edits, dimension and entity inspection, drawing QA, DWG/DXF batch operations and schematic-to-solid exploration. Requires a STEP import/export experiment and explicit unit/frame checks before reliance on neutral 3D solids. Avoid assuming document history carries through arbitrary Boolean or file conversion operations.

### FreeCAD

FreeCAD is an LGPL-2.1-or-later open-source parametric modeler with native document tree, constrained Sketcher geometry, Part Design additive/subtractive operations, Part B-rep, Draft 2D tools, TechDraw drawings, assembly workbenches and broad import/export. The Python API can create constrained sketches, Part shapes/features, recompute documents, edit properties and export BREP/IGES/STEP/STL. Native `.FCStd` is the appropriate editable project source. Imported STEP is generally exact solid geometry whose original feature history is absent; mesh objects remain mesh data.

No core external AI service is required. Scripting runs inside the application Python environment and GUI API; headless behavior varies by build and should be validated with a pinned FreeCAD executable/version. Python workbench/addon code and FreeCAD's own LGPL licensing have separate implications. Avoid depending on proprietary cloud CAD services.

Primary sources: [FreeCAD source/licence](https://github.com/FreeCAD/FreeCAD), [Sketcher Python scripting](https://github.com/FreeCAD/FreeCAD-documentation/blob/main/wiki/Sketcher_scripting.md), [Part scripting](https://github.com/FreeCAD/FreeCAD-documentation/blob/main/wiki/Part_scripting.md), [Python scripting tutorial](https://github.com/FreeCAD/FreeCAD-documentation/blob/main/wiki/Python_scripting_tutorial.md), [Part Design concepts](https://github.com/FreeCAD/FreeCAD-documentation/blob/main/wiki/Part_and_PartDesign.md). Inspected 2026-11-12.

Fit: primary authoring tool for constrained sketches, dimension-driven solids, assemblies and production drawings; useful as an agent skill target because it offers exact geometry and an inspectable document tree. Risks include fragile references to generated face/edge indices (topological naming changes), version-dependent workbench APIs and scripts that produce a final shape without a useful feature tree. Skills should instruct agents to use stable datums, named parameters, one body per part, recompute, validate shape and preserve the native document.

### CadQuery

CadQuery is an Apache-2.0 Python parametric CAD scripting framework over OCCT/OCP. It models exact B-rep geometry, assemblies and sketches through Python operations, and imports DXF/STEP/XML/XBF; exports DXF/SVG/STEP/STL/AMF/3MF/glTF/XML/XBF. Official documentation says its own Python source is the only fully parametric representation; exchange files do not carry CadQuery parametric data. DXF profiles can be imported and extruded. Python environment, OCCT bindings and visualization dependencies are required; no online AI service is intrinsic. CQ-editor is an optional GUI/editor, not required for the kernel.

Primary sources: [CadQuery repository/licence](https://github.com/CadQuery/cadquery), [official docs](https://cadquery.readthedocs.io/en/stable/), [import/export formats](https://github.com/CadQuery/cadquery/blob/master/doc/importexport.rst). Inspected 2026-11-12.

Fit: mature code-based alternative for repeatable dimensioned parts; good for exact geometry and source-controlled parameter families. The agent must preserve source parameters and document units, not deliver STEP alone. API generation/version should be pinned; geometric selectors can also be sensitive to model changes.

### build123d

build123d is an Apache-2.0 Python parametric B-rep framework built on OCCT, refactored from CadQuery. It supports explicit 1D/2D/3D types, sketch/part builders, algebraic composition, joints/assemblies and import/export including STEP, STL, DXF/SVG and meshes as supported by its current docs. The Python program is the design history; STEP is the interoperable geometry. It needs Python plus the OCCT/OCP stack and usually a separate viewer such as ocp_vscode. No remote AI service is inherent.

Primary sources: [build123d repository/licence](https://github.com/gumyr/build123d), [official docs](https://build123d.readthedocs.io/en/stable/), [import/export guide](https://build123d.readthedocs.io/en/stable/import_export.html). Inspected 2026-11-12.

Fit: recommended code-CAD option for Python-native mechanical parts and reusable parameterized geometry. Pre-1.0 API movement and OCCT platform dependencies require a locked environment and executable smoke tests. It does not offer its own full graphical CAD editor.

### OpenSCAD

OpenSCAD is GPL-2.0-or-later source-based constructive solid geometry. `.scad` describes parameters, primitives, transformations, booleans, modules and 2D-to-3D extrusion; the source is editable and reproducible. It imports DXF/SVG as 2D, plus STL/OFF/AMF/3MF meshes; outputs include STL/3MF/AMF/OFF and 2D DXF/SVG/PDF depending version/build. A mesh export contains facets, not editable analytic B-rep or constraint history. No AI/cloud service required; command-line rendering is scriptable.

Primary sources: [official documentation](https://openscad.org/documentation), [language reference](https://files.openscad.org/documentation/manual/The_OpenSCAD_Language.html), [source repository/licence](https://github.com/openscad/openscad). Inspected 2026-11-12.

Fit: a strong low-overhead route from explicit dimensions or 2D DXF/SVG profile to repeatable solid-like CSG and mesh outputs. Useful for custom brackets, fixtures and variant families with simple CSG. Roundtrip into exact engineering B-rep is outside its normal export path; native source should remain alongside meshes.

### Blender automation

Blender is GPL-licensed and exposes Python `bpy` for scenes, objects, curves, mesh datablocks, modifiers, geometry nodes, rendering, import/export and batch background execution. Its central representation is the scene graph and polygonal mesh/curve data, with procedural modifiers/nodes; that is distinct from a constraint-based mechanical B-rep feature tree. It can generate precise coordinates and dimensions, but mesh topology and modifier application do not create an OCCT solid model. Blender can be driven locally without an AI service; proprietary text/image-generation add-ons or hosted services are separate optional integrations and should be excluded from a fully open workflow.

Licence details for the upstream source, installed package and MCP integrations are recorded in [domains and components](domains-and-components.md). Primary sources: [Blender repository/licence](https://github.com/blender/blender), [Python API quickstart](https://docs.blender.org/api/current/info_quickstart.html), [Mesh API](https://docs.blender.org/api/current/bpy.types.Mesh.html). Inspected 2026-11-12.

Fit: use for photogrammetry/scan mesh repair, image-based reconstruction, visual inspection, scenes and rendering, and geometry-node procedural assets. Use FreeCAD/OCCT to remodel measured scan geometry into engineering solids and to attach dimensional constraints. USD/glTF/OBJ transfers commonly preserve scene or mesh content but not CAD design intent.

### SolveSpace

SolveSpace is GPL-3.0 free 2D/3D parametric CAD with a constraint solver and sketch-driven parts/assemblies. It supports dimensioned sketches, extrusions, revolves and assembly constraints, and imports/exports common 2D/3D exchange formats including DXF, STEP, STL and SVG according to its documentation. Native `.slvs` retains constraints and construction; STEP transfers B-rep geometry while STL transfers mesh. It is a standalone local application with no AI-service dependency and exposes documented file formats, rather than the broad scripting/MCP surface of FreeCAD.

Primary source: [SolveSpace official site](https://solvespace.com/), [source repository and GPL licence](https://github.com/solvespace/solvespace). Inspected 2026-11-12.

Fit: lightweight constrained sketches and parts, especially when simple native 2D/3D constraint workflows suffice. Assess assembly complexity, Python automation and current maintenance before using as the central agent automation target.

### Open CASCADE Technology (OCCT)

OCCT is a LGPL-2.1-with-exception C++ library/platform, not a complete end-user CAD application or agent skill. It supplies exact geometry/topology, B-rep modeling algorithms, mesh operations, visualization, STEP/IGES exchange and application data support. Python wrappers such as OCP underlie CadQuery/build123d. Its APIs support application development, not a turnkey text-to-model workflow; developers must implement sketch dimensions/constraints, document/feature history, GUI, validation and file workflow or use FreeCAD/CadQuery/build123d.

Primary sources: [official OCCT overview](https://dev.opencascade.org/doc/overview/html/index.html), [OCCT source repository/licence](https://github.com/Open-Cascade-SAS/OCCT). Inspected 2026-11-12. Commercial/proprietary uses need licence review against the exact OCCT distribution and linked components; do not assume every wrapper or dependency shares OCCT's terms.

### DXF and SVG profile workflows

DXF stores 2D/3D drafting entities, layers, blocks, dimensions and application records; SVG stores vector paths, units/viewBox, text and styling. Neither file alone states a reliable mechanical datum or guarantees a closed planar profile. Before turning a drawing into a solid, preserve original and record file hash, units, layer selection, sketch plane, geometric transforms and interpretation of dimensions; report open endpoints, duplicates, self intersections and unsupported entities. Convert only a copy into an editable sketch, constrain it, then make named features.

For programmatic DXF reading/writing, ezdxf is MIT licensed Python; it supports multiple DXF generations, ASCII/binary DXF and retains third-party data, with documented add-ons for SVG/PDF plotting, text-to-path, OpenSCAD, and other tasks. It does not itself provide parametric solid modeling. SVG can be imported into FreeCAD, OpenSCAD, build123d and graphics tools; paths may need flattening/curve conversion and unit normalization. Primary sources: [ezdxf documentation/licence/dependencies](https://ezdxf.readthedocs.io/en/stable/), [OpenSCAD profile import](https://files.openscad.org/documentation/manual/The_OpenSCAD_Language.html), [FreeCAD Sketcher scripting](https://github.com/FreeCAD/FreeCAD-documentation/blob/main/wiki/Sketcher_scripting.md). Inspected 2026-11-12.

## Proposed skill catalogue for this repository

1. **`engineering-input-to-cad` (new project skill):** parse text, dimensions, photo references and drawing sheets into a labeled input table (value, units, source, confidence/status), unresolved-ambiguity list and coordinate-frame statement; generate a constrained sketch or a cited proposal; preserve source unchanged; require explicit feature/part boundaries. Do not guess missing dimensions or select a design from alternatives.
2. **`freecad-parametric-part` (adaptation proposal):** create `.FCStd` parts from named parameters and constrained sketches; prefer datum planes/axes, stable references, explicit units and one PartDesign Body per solid part; retain human-readable labels and feature tree; recompute; check validity/solids/bounds/volume; export STEP only as a derivative and compare imported B-rep measurements.
3. Reuse `${CODEX_HOME}/skills/ocs-engineering/SKILL.md` for OCS MCP and geometry work. Revise that skill only from observed usage gaps; do not create a parallel OCS drawing skill in this catalogue.
4. **`code-cad-part` (adapted between build123d/CadQuery):** select one pinned library/version, preserve executable Python source, declare units and inputs, validate B-rep before export, create STEP with units and assembly labels, and inspect STEP by reopening in FreeCAD. Do not mix API dialects or rely on mesh-only output for engineering geometry.
5. **`openscad-csg` (adapted):** generate `.scad` with named parameters/modules and explicit `$fn` resolution; call command-line parser/render separately; preserve source; export STL/3MF/DXF/SVG according to 3D/2D result; check mesh topology and orientation in an independent tool.
6. **`drawing-profile-to-solid` (new):** copy DXF/SVG; identify unit, layer and origin; normalize transforms; extract target profile; reject non-closed/self-intersecting or ambiguous paths; constrain sketch; log all geometry changes; compare resulting profile bounds/area with source dimensions.
7. **`scan-to-engineering-model` (new, later):** use Blender/photogrammetry only for reconstruction and mesh cleanup; store camera/calibration/scale evidence and mesh status; derive measured references; remodel into exact CAD faces/features in FreeCAD/OCCT and keep source scan, mesh and remodeled CAD linked.
