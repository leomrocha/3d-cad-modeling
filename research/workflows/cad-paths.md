# CAD input paths and combined workflows

Research date: 2026-11-12. Status: proposed workflow map based on current project sources, local OCS and skill findings, and primary documentation/papers opened for this batch. No CAD workflow was executed in this batch. OCS remains the project baseline because the project selected it and the user reported partial success with the installed `ocs-engineering` skill. FreeCAD is a proposed complementary backend for constrained sketches and feature history. `cad-paths.json` is the machine-readable operation/recipe/idea index; `cad-sources.json` records every source linked here.

## Route selection

Select a route by the input representation, output requirement and evidence available:

| Input and goal | Route | Preserved design meaning | Main checks |
|---|---|---|---|
| Text plus explicit dimensions → a reusable part | Model brief → OCS live geometry or build123d/CadQuery source; FreeCAD when editable sketch/feature history is required | Source wording, dimension provenance, units, datums and parameter names; parametric source stays in its owning application/source file | Input-to-parameter mapping, units/frames, exact dimensions, solid validity, save/reopen and independent bounds/volume |
| Raster sketch → dimensioned profile | Calibrated image plane → image cleanup/OCR and line/vector extraction → human reconciliation → constrained sketch → feature | Original raster and image coordinates; accepted dimensions; explicit line-to-constraint mapping | Scale controls, OCR transcription review, line endpoints, profile closure, constraint residual/degrees of freedom, final dimensions |
| Raster floor plan → building geometry | Page rectification/scale → wall/opening/room segmentation or manual trace → topology graph → editable vector drawing → wall/opening solids and levels | Pixel source, scale/control measurements, wall/opening graph, inferred versus measured geometry | Pixel-to-world transform, wall thickness and opening checks, room connectivity, parallel/perpendicular constraints, elevations and source-linked uncertainties |
| DXF/SVG → profile/part | Inspect units/layers/blocks and entities → preserve source → select/clean profiles → constrain/repair in FreeCAD or construct in build123d → extrude/revolve/sweep | Source entities, layer provenance, units and transformations; explicit changes from source curves | Open/duplicate/self-intersecting edges, closure tolerance, profile area/bounds, unit and plane checks, solid count/validity |
| Raster orthographic views → 3D interpretation | Rectify/crop individual views → recover scales/view axes → register front/top/side projections → match lines/features → construct 3D edge graph → faces/features → fit constraints | Each input view and view registration; correspondence alternatives; explicit unresolved depth/occlusion | Shared dimensions across views, projection residuals, topology, dimensions, ambiguity list, rendered-view comparison |
| Photo set/video/depth → CAD remodeling | Calibration → camera pose/scale solution → point cloud/mesh → fitted planes/cylinders/axes → measurement set → parametric remodel | Original image/depth observations, calibration, metric controls, fitted feature evidence and residuals | Reprojection, independent scale lengths, registration residuals, held-out surface distances, interface dimensions, watertightness for mesh only |
| Existing solids/library parts → assembly | Intake/license/hash → read representation and units → normalize occurrence frames → assign interfaces/joints → check interference/motion | Native component file, source identity, frame, transformations and part boundaries | Component ID and hash, units, interface alignment, occurrence transforms, solid/mesh distinction, collision/motion bounds |

### Evidence rules for interpretation

1. A measured dimension is a value explicitly supplied by a measurement or dimension annotation whose reference geometry and units are identified. Keep the image coordinates and the dimension's feature association.
2. An inferred dimension is derived from pixels, projection correspondence, symmetry, a pattern, a CAD-library match or an engineering hypothesis. Label its method, evidence and uncertainty beside the value. It does not become measured when the sketch solver is fully constrained.
3. A constraint is a chosen geometric relation or numerical value imposed on a model. It may encode measured evidence, source annotation, or an explicit design choice. Keep those origins separate.
4. An occluded backside, hidden plan dimension, raster symbol or missing third view has no direct observation. Leave it as a parameter, state alternative reconstructions, or ask for a reference. A visually plausible mesh does not supply missing engineering evidence.
5. A user-selected standard/library component may constrain interfaces only when the selected part identity and source geometry are recorded. Similar visual shape does not establish exact part identity.

## Operation map

The JSON contains the full input/output and prerequisite declarations. The principal transitions are:

1. **Brief extraction (`CAD-01`)** preserves original wording and converts explicit statements into source-linked `model-brief` fields. It records units, datums, component boundaries, value status and unresolved geometry.
2. **Image plane rectification (`CAD-02`)** uses known coplanar controls and dimensions to produce metric drawing coordinates. A planar homography rectifies that plane and does not infer depth. The separate camera-calibration route (`CAD-02B`) estimates camera parameters/poses from photographs and known controls.
3. **OCR and raster-vector candidates (`CAD-03`, `CAD-04`)** produce text boxes/strings, line endpoints and contours. Tesseract TSV reports text, bounding boxes and confidence; OpenCV functions return image-space line/contour candidates. Review glyphs and feature meaning against retained source pixels.
4. **Floor-plan topology (`CAD-05`)** creates wall/opening/room candidates and graph connections from a scaled plan. Published floor-plan methods describe recognition, vectorization and structural graph reconstruction as research workflows; no paper citation here asserts an installed tool.
5. **Orthographic registration/reconstruction (`CAD-06`, `CAD-07`)** requires a bundle of identified vector views, a shared projection convention, dimensions and confirmed feature intent. Published methods propose cross-view correspondence and candidate shape construction; inferred geometry must be projected back into every input view and checked against dimensions.
6. **DXF/SVG intake (`CAD-08`)** preserves the source and records importer/entity changes. FreeCAD documents DXF and SVG entity coverage and options; `ezdxf` documents programmatic DXF access. Import behavior, unsupported entities, units and SVG scaling must be checked for the actual file.
7. **Constrained planar sketch (`CAD-09`)** attaches geometric and dimensional relations to a source-linked profile. A satisfied solver means the constraints are internally consistent; it does not prove that the constraints match the source.
8. **Kernel solid creation (`CAD-10`)** builds a `cad-solid` from a constrained sketch, parametric source or explicit model brief plus dimensions. FreeCAD, build123d and CadQuery document B-rep modeling APIs. The OCS checkout has native geometry, while its inspected STEP writer consumes tessellated meshes and produces faceted STEP.
9. **Measured scan remodeling (`CAD-11`)** fits planes, cylinders and axes to calibrated/registered image, depth, point-cloud or mesh data. Record the source samples, frame transforms, fit residuals and hidden/uncertain regions beside each fitted value.
10. **Assembly (`CAD-12`)** places identified solids/library components using named interface frames. Preserve part identity, units, occurrence transforms and source hashes; record placeholders and inferred clearances explicitly.
11. **Verification and recovery (`CAD-13`, `CAD-14`)** read back saved geometry and record check values, artifact identity and failed steps in `verification-report`. Recovery uses that report to revise the affected brief or earlier transition.
12. **OpenSCAD mesh export (`CAD-15`)** evaluates source-defined CSG into a `mesh` derivative. Keep the OpenSCAD source as the editable parameter record; do not type the exported mesh as a B-rep solid.
13. **Floor-plan solids (`CAD-17`)** extrude a reviewed wall/opening graph using explicit vertical dimensions and produce a CAD assembly. The plan image alone does not provide missing heights or concealed build-ups.
### Why alternative routes remain separate

- **Manual constrained sketching** is a reasonable route when drawing annotation and topology are clear and the cost of image segmentation is greater than tracing. It makes line-to-source review easier.
- **Raster automation then human reconciliation** suits repeated floor plans or clean, dimensioned scans. Image segmentation is efficient for candidates; human review resolves symbol meaning, occlusion and construction conventions.
- **Code-CAD** suits explicit dimensions, repeated families and auditable geometry. It does not recreate a GUI feature tree inside OCS; source code is the parametric record.
- **OCS** suits the project's established interactive drawing/session route. Its installed skill constrains context, session revisions and readback. Its STEP route is faceted; select an exact B-rep path when analytic surface exchange is required.
- **FreeCAD** suits construction-history editing, constrained sketches, imported profile repair and parametric features. It is complementary to OCS rather than a replacement decision.
- **OpenSCAD** suits source-defined CSG when mesh output is sufficient. `CAD-15` records source-to-mesh conversion separately from `CAD-10` B-rep creation.
- **Blender** suits scene/mesh review, segmentation visualization, scan mesh cleanup and reference rendering. Its mesh/scene data does not become a dimension-constrained solid by changing file extension.

## Combined workflow recipes

Each recipe has a distinct operation sequence in `cad-paths.json`.

1. **Text + dimension table → editable part:** extract brief → identify input/status for each parameter → select OCS for the established project session or FreeCAD/code-CAD for the required feature tree → construct → read back → export requested derivative. Every parameter points to source text, drawing or declared assumption.
2. **Raster sketch + measured scale → constrained profile:** retain source image → calibrate planar scale with two or more known controls (or a documented ruler/scale) → propose OCR/curve extraction → compare OCR and strokes against pixels → manually confirm feature associations → constrain sketch → close profile → extrude → compare profile and final dimensions.
3. **Floor plan image + printed dimensions → wall/opening CAD assembly:** rectify image → use OCR and line/segmentation candidates → resolve labels to geometry → review the wall/opening graph → provide confirmed floor datum, wall heights/thickness conventions and opening elevations in the model brief → generate separate wall/opening solids and check plan topology and dimensions. The result is a CAD assembly; IFC classification needs a separate semantic workflow.
4. **DXF/SVG + part requirements → solid:** preserve and inspect source → reconcile unit/layers/blocks and projection plane → select contours → repair under a change log → constrain/extrude/revolve in FreeCAD or code-CAD → save native source and independent exact-solid export → inspect manifold and dimensions.
5. **Three orthographic views + a dimensioned view → parametric reconstruction:** vectorize each view with preserved raster/source association → register projection axes and scales → match edges and vertices across views → create a candidate 3D wireframe → test competing edge/face constructions against all views and dimensions → build native constrained features → project the result back into each source view. The papers support research methods for candidate reconstruction; their learned or inferred features require review.
6. **Photo set + one caliper measurement + library candidate → measured assembly:** use COLMAP/Meshroom-style SfM/MVS with measured controls to estimate camera poses and visible cloud/mesh → inspect image coverage/reprojection and independent length residuals → fit part interfaces and retain residuals → compare library identity/geometry → preserve a matched library part or label remaining modeled shape as inferred → assemble by named frames and check interface dimensions.
7. **Depth frames + existing STEP housing → remodel only one interface:** register the depth scan to the retained exact housing using shared datums/control points → segment the replacement component → fit measured planes/cylinders → compare cloud residual and mating coordinates → remodel only the scoped component in FreeCAD/build123d → assemble against the source STEP copy and compare interface measurements. Keep source housing unchanged and report scanned surface data separately from analytic fit.
8. **Model-library assembly + missing fastener → complete assembly:** retrieve an identified library component or keep a parametric placeholder → align stable part interface frames → keep occurrence IDs and transforms → check clearances only where geometry supports the check → distinguish source parts from placeholders.
9. **OpenSCAD source → mesh derivative:** retain the parametric source → render/export the mesh → reopen and check units, bounds, normals, watertightness and source dimensions → record checks as a verification report. The output remains a mesh.

## Open research questions and proposals

1. **Raster dimensions:** Which scan preprocessing settings preserve fine dimension arrows and diameter/diameter symbols while OCR improves? Proposal: use separate OCR and geometry layers, never erase the source pixels, and store corrected text overlays with confidence and manual review state.
2. **Orthographic reconstruction:** Which open implementation accepts standard engineering projections and outputs editable feature history rather than a closed mesh/solid only? The papers establish research methods, not a production-ready open backend. Compare candidate outputs with FreeCAD reconstruction fixtures before recommending a runtime.
3. **Constraint solving:** A fully constrained 2D sketch can still be semantically wrong. Keep constraint parameter IDs linked to the input evidence table and perform an independent source-to-model value check.
4. **Raster-plan height ambiguity:** 2D plan imagery does not directly encode elevation, section build-up or concealed construction. Keep z-coordinates separate from plan-view wall topology and require elevation/section/known floor-to-floor measurement for those values.
5. **Mixed inputs:** A photo, drawing and library CAD may disagree. Keep a per-feature evidence ledger with source coordinates, uncertainty and selected source priority; use assembly-level alignment controls to report disagreement rather than silently warping a library part.
6. **Round-trip quality:** Source export capability statements do not verify an installed writer. Use the same analytic test part across OCS, FreeCAD, build123d/CadQuery and OpenSCAD; reopen each output in a second independent application and compare units, bounds, solid count, surface types, dimensions, volume and feature-history status.

Existing report and local source observations are explicitly registered with their path and evidence class.

The machine-readable map adds `verification-report` for a saved set of check results, failed operation identifiers, affected artifacts and revision/hash; this type supports failure diagnosis without pretending that diagnostics are CAD geometry. In the JSON contract, `inputs[]` are AND requirements; when `input_alternatives` exists, every shared input is required and one alternative group must also be satisfied. Each alternative group is an AND set. Listed outputs are guaranteed for each accepted branch.
