# Reusable retained-artifact verification

Date: 2026-11-13. Implementation and verification: gpt-6.1-sol.

1. Repeated component retention checks encountered stale derivative hashes, work-only rows with null retained paths, repeated attributions to the same file, named-root locators and case code retained outside the check-packet directory. The reusable helper `scripts/retained_artifacts.py` replaces the repeated ad hoc read-only checks for these supported formats.
2. It reuses `component_records.observe_file` and existing root-resolution/portable-output functions. It selects retained hashes independently from original hashes, verifies current bytes, parses saved JSON/JSONL, checks declared path boundaries and compares the manifest before/after verification. It imports no CAD client and performs no native operation.
3. Seven synthetic tests passed: current derivative association across portable path forms; changed-byte detection; literal-backslash JSON rejection even with a matching hash; explicit work-only omissions and empty-pass rejection; repeated attribution versus conflicting hashes; path escape/missing hash rejection; and explicit-root case-code references outside the packet.
4. Initial real-packet checks rejected repeated file attribution and a source-root case-code path. Inspection established these as supported provenance structures; the helper now reports identical attributions separately and allows paths within an explicitly supplied root. The final real-packet pass verified unique retained file counts of 19 for Curtis, 28 for Kelly with two additional matching attributions, 33 for Pilz, 29 for Albright and 41 for Altec. Saved JSON records parsed successfully. Earlier manual counts described manifest entries; the helper reports unique files explicitly.
