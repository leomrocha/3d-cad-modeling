# Create navigable CAD models

Use the [operation selection procedure](references/modeling-operation-selection.md) for component reuse, provider capability checks and job evidence. Apply it to the requested operation.

1. Tell the user that reusable scripts, assignments, model revisions and evidence stay in the local project. They may opt to contribute generic improvements later. Reconcile existing models and source evidence before building anything.
2. Establish a definition ID for each distinct part and an occurrence ID for each installation. Give retained items readable labels, roles, parents, native layers or groups and useful tags. Two copies of one fastener share a definition and have separate occurrences. Bind a finish, display colour and physical material individually to the source and scope (definition, instance or face). Keep unknown material empty. If sources do not identify the owner of an assignment, ask before writing it.
3. Use the chosen CAD application. Discover native label, layer, group, selection, visibility and custom property operations on that connection. In OCS inspect the actual entity/common properties and layer table. Use entity selection and native properties for navigation; an operation journal label or an XDATA string alone does not create a selectable layer. In Blender use collections for isolation and stable custom properties for identities. In FreeCAD distinguish internal Name from editable Label and inspect group membership. Record any required function the application cannot perform before proceeding.
4. For a DXF source inspect source layer, effective layer, layer-table flags, indexed/true colour and INSERT overrides. The [style inspector](scripts/dxf_styles.py) reads modelspace or a named layout with ezdxf and resolves display properties through the containing INSERTs. Keep source handles and occurrence paths with the geometry handoff.
5. Write assignments when creating each retained body or inserting an instance. Resolve the result of Boolean or replacement operations and reapply or verify its fields. Record the expected inventory from the job independently of the native readback. For each saved checkpoint retain native file hash and exact skill commit in the job.
6. Reopen the derivative. Enumerate native objects independently, recover IDs from the file and traverse real parents and layer/group membership. Compare expected and reopened inventories with the [inventory verifier](scripts/verify_navigation.py). Both take the form {"objects":[{"id":"rear-pin","definition":"pin","parent":null,"label":"Rear pin","role":"pivot","layer":"Hardware"}]}. Include required tags, physical_material, display_colour and other fields under identical names on both sides; use consistent units and typed representations. Parent is null for roots. The verifier compares fields and membership; actual select/isolate operations and geometry checks require their own evidence.
7. Find an occurrence from its readable role, select it, isolate its group, inspect its properties, verify an unaffected sibling and restore visibility. Capture full, interface and fixed-camera isolated views. Before exchange identify destination property support. Reject an incompatible required handoff until the user chooses a different format or accepts a documented loss. Repeat the lookup on the reopened exported file. Offer a contribution preview only after local validation.

For nested assemblies, cut joints, catalogue handoffs and recorded layer demonstrations, use the [saved assembly checks](references/assembly-validation.md).
