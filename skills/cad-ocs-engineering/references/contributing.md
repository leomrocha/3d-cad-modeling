# Contribute an improvement from a completed job

1. **Offer a local preview.** After [component completion](component-completion.md), name the specific reusable change and its use. Ask whether the user wants to prepare a local contribution preview. A decline or silence ends the contribution steps. A later request can resume from the same job record. Jobs without a reusable change end with their ordinary report.
2. **Find the verified files.** Use the existing reusable_improvement row, changed_files pins and verification results. Resolve the owning project's [named roots](paths.md). If a hash differs, locate the verified revision or check the newer version and label it in the preview. Use a separate local checkout of the skills repository supplied by the user.
3. **Identify the changed lines.** Compare the original installed bytes or matching local baseline revision with the verified job version. Compare that diff with the current canonical source. Use the installed package manifest to identify bundled paths and content hashes. If the original is unavailable, show the individually attributable changes and identify uncertain overlap for the user. A digest identifies a revision; the diff identifies the lines. When the change is already present, show the matching behavior and skip the duplicate.
4. **Show the local preview.** For each candidate show its purpose, canonical destination, exact diff and any test input proposed for sharing. Map bundled helpers to the checkout's canonical scripts directory and procedures to the owning skill. Extract the generic lines from mixed files. Keep project geometry, dimensions, recipes, drawings, captures and full logs in the modeling project. Let the user narrow the scope before preparing the branch.
5. **Prepare one local branch per improvement.** Record the base revision, create the contribution branch in the skills checkout and make the checkpoint required by that checkout. Apply the scoped source changes while preserving concurrent edits. Run the focused check with shareable inputs. Follow the checkout's package maintenance instructions for catalogue and source registration. For helper, dependency or skill changes run `python3 scripts/build_skill_packages.py --finalize` and then `python3 scripts/build_skill_packages.py --verify` with the required local dependency roots. Inspect the generated package diff and commit the scoped source and package files together.
6. **Show the final publication scope.** Present the full base-to-commit diff, generated files, check commands and observed results. Draft the pull request with the original problem, reusable change, reproduction instructions and observed result. Identify the exact commit, source branch, destination repository and target branch. Ask: “Do you want me to push this branch and open a GitHub pull request with the changes shown above?” Wait for an explicit yes. A decline or silence leaves the branch local. If the proposed revision or destination changes, show the updated scope before publishing.
7. **Submit the approved revision.** Push the displayed branch to the approved destination and open the pull request against the displayed target. After successful submission, record its URL and submitted commit beside the original job evidence. If either operation fails, report which action succeeded and retain the local branch.
