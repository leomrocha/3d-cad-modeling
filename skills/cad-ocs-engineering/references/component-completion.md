# Component completion gate

1. Preserve IN_PROGRESS models and supporting files after each meaningful modeling step, before risky operations, switches and handoffs. Save the created owned document immediately to its authorized location. Verify each persistent checkpoint's path/hash and record the current document/geometry revision and completed operation. Keep the previous verified checkpoint. A failed or uncertain save stops further modeling until persistence is established through original-request recovery. Completion requires another save.
2. Use `completion_check` in [component records](../scripts/component_records.py) to evaluate the caller's final job. Supply a readable job ID, saved model `{path,sha256}`, explicit root map for stored named-root paths, and evidence rows for `source_geometry`, `metadata`, `persistence`, `cleanup` and `reusable_improvement`. Each row has `result=PASS`, the same `job_id` and the exact `model_sha256`. These are independently produced check receipts; the gate aggregates their status and validates artifact pins.
3. The reusable improvement row additionally requires `applied=true`, nonempty `changed_files` with actual path/hash pins, and named passing `verification` rows. Record the generic behavior changed, its regression and any actual native application separately. A proposed improvement or failed check keeps the job IN_PROGRESS.
4. Final geometry and metadata checks cover the completed saved revision. Use the exact reopened document when reopen is authorized. For an explicitly required save-only task, bind completed-save/audit, file hash and current owned geometry/metadata evidence to that revision and record `verification_reopen=false`; follow [persistence operation selection](surface-mesh-recovery.md#respect-the-callers-persistence-operation). Cleanup closes only completed owned documents under the [cleanup procedure](document-cleanup.md). Keep source originals, partial checkpoints, failed-attempt evidence and final artifacts in caller-owned storage.
5. DONE requires every gate check to pass. The gate returns IN_PROGRESS with individual failed checks otherwise; it preserves files and sends no CAD operation. Report actual execution model identity when available, otherwise unavailable. Record acceptance separately.
