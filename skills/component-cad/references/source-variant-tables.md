# Exact product rows and variant columns in source tables

Use `${MODELING_ROOT}/scripts/source_variant_table.py` when a manufacturer or engineering table places specifications for multiple variants in adjacent columns. The helper selects one cell from an explicitly transcribed table using the exact column header and exact row label.

1. The caller records the original source URL or local source path, retrieval or observation date, source title, content type, source hash when a file was retained, the table location, and a reviewer-checked transcription. The helper does not fetch, parse, authenticate, or compare the transcription with the source.
2. Supply a table object with the numbered fields `table_id`, `source_location`, `headers`, and `rows`. `headers` preserves the source column labels. Each row contains `label` and a `values` list in the same order as `headers`; each row must have one nonempty string cell per header.
3. Call `select_cell(table, variant_header, row_label)` with the exact source header and row label. The returned record includes the selected header, row, raw cell text, source table location, and header index. The result records a table transcription association; it does not establish the authenticity of that transcription or the physical accuracy of the source claim.
4. The helper rejects missing or repeated headers, a header with no exact match, repeated row labels, malformed rows, empty cells, and a missing exact row label. Header and row duplicate detection is case-insensitive after trimming whitespace; selection itself requires exact case-sensitive text.
5. Keep adjacent variant values as separate source claims. A value from a neighboring column cannot support the requested product unless the source explicitly maps that column to that product.
6. Apply product-specific units, evidence status, original source URL/path, source hash, date, and concrete feature checks in the external component job. A successful selector result is not a geometry or native CAD check.
7. For a catalogue with product variants in rows and named dimensions in columns, keep that original orientation. Pass the exact dimension-column label as the second argument to `select_cell` (its current parameter name is `variant_header`) and the exact product code as `row_label`. The returned column and row identify the source claim together. Retain neighboring rows as separate products and each dimension letter's drawing-leader endpoints separately from its tabulated value.

8. When a source cell has a missing separator or an apparent transcription error, retain its exact raw text and the complete row/column header. Record the reviewed ordered values separately, with the page/image location and the evidence used to read the sequence. Bind the construction inputs to that explicit interpretation; keep the raw source unchanged. If the source views support more than one ordering, retain that ambiguity as a named input gate before dependent geometry. A selector result alone does not resolve malformed source text.

9. When dimensions come from a family drawing, record the family identity, source revision, page/view and option scope beside each dimension. Name the geometry for that source family and configuration. Keep the candidate part number's association with that family as a separate evidence record. Keep dimensions from different revisions and optional configurations in separate contracts unless the source explicitly combines them.
10. On a page containing several products and a shared image gallery, bind the dimension row and image independently to the exact product code. Retain the row labels and units, the page's image-to-variant mapping when available, and the inspected image. An exact table match establishes the selected source values; use the separate image association to identify which visible features belong to that product.
11. For standard fasteners, record the standard name, edition, product grade and exact diameter/length row used for geometry. Preserve a seller's combined standard designation and a manufacturer's similarity statement as attributed product claims. Bind each modeled dimension to its own standard table and drawing. Give a standard-dimensional reference its standard name; keep the exact seller product association as a separate record. Hexagon width, overall height and bearing-face geometry can change between standard editions.
12. Retain each fastener symbol with its drawing endpoints and value type: nominal value, minimum, maximum, reference value or range. Record nominal thread diameter, pitch, entry diameter, usable thread length, incomplete-thread region and plain-shank length as separate features. A dimensional reference identifies its represented surfaces and its metadata-only features. Keep literal malformed seller text alongside the separately sourced standard value and the actual evidence used for that interpretation.

`tests/test_source_variant_table.py` uses synthetic table records. It checks exact column association, duplicate and malformed input rejection, and neighbor-column separation. It does not inspect a product source or validate a component.
