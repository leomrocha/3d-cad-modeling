# Component source and action record procedure

1. **Index reading:** `scripts/part_index.py` accepts explicit `--index` paths. It reads a FERME-style component list or an existing dictionary with `entries`. `--id` selects an exact identity; `--query` matches all supplied case-insensitive text terms in the original record. Returned rows retain record kind, source path, source SHA-256 and original fields.
2. **Job readiness:** provide `job_id`, `part_id`, readable `part_name`, required representation, units, frame and a nonempty `features` list with at least one explicitly required feature. Each supplied value carries unit, evidence status, source file/digest and source location. Each unresolved required feature carries its exact question. Source mutation invalidates the observation. Source file hashing uses a streaming buffer and checks identity/size/timestamps around capture.
3. **Command:** `python3 scripts/component_records.py ${SOURCE_ROOT}/component-project/job.json`. Exit 0 means `SOURCE_READY`; 1 means `NEEDS_INPUT` with feature-specific questions; 2 means invalid records or failed I/O/source checks. Keep those source results distinct from later CAD measurements. `require_ready(job)` raises before any caller can enter dependent geometry construction when source coverage fails.
4. **Action occurrence:** `append_occurrence(path, record)` writes an append-only JSON line under a file lock and rejects a reused occurrence ID. Required content: readable action and component IDs/names; job; inputs/outputs/prerequisites; software/agent; representation/units/frame; preserved and changed/inferred information; alternatives; downstream operations/conditions; checks; actual result and evidence links. Retain failed attempts with their own identities. Current result labels are `PASS`, `FAIL`, `NEEDS_INPUT` and `UNKNOWN`.
5. **Ownership:** FERME retains its existing component index and parts/standards dictionary. New job/action evidence is under its CAD work records. This project's scripts read those explicit paths; records/data retain their owning project. Query results support access to those records and preserve their original evidence status.
6. **Observed first case:** the rail and crossmember source sheets give 40 x 40 x 3 mm proposed sections and 600/260 mm proposed cut lengths. The first rail's source capture succeeds; its corner-profile requirement produces a named input decision. The test suite checks this gate, pinned-source changes and exact source-record preservation using independent fixture expectations.
7. **Bundled OCS code:** `scripts/cadtools/` supplies guarded execution, geometry and save/reopen checks. `scripts/ocs_control.py` supplies the existing-session transport. Read [OCS runtime instructions](ocs-runtime.md) and bind all jobs, source values, documents and output locations explicitly.
8. **Final retained evidence:** use the [retained artifact manifest check](retained-artifact-checks.md) after the final derivative/provenance changes. It verifies actual retained hashes and saved JSON, records work-only omissions, and distinguishes unique files from repeated provenance attributions. Retain the successful receipt in the component project before committing the component result.
